# 日志取证

日志排查最容易犯的错是「搜不到关键字就说没问题」。先分清三种情况：
日志根本没采集到、采到了但不在这个时间窗、以及确实没有该关键字。

## 1. 先确认日志是否在流动
- 取实例最近日志（`agent_get_instance_logs`）。
- 若为空：先查该实例是否刚启动、Worker 心跳是否正常。
  **空日志不等于无异常**，它更可能是采集链路问题。

## 2. 收窄时间窗，不要全文检索
- 用发生异常的时间点前后各 2 分钟作为窗口，而不是整个文件。
- 多实例同时出现异常时，用同一时间窗横向对比，先判断是实例问题还是节点问题。

## 3. 区分类别再下结论
- JVM/进程退出：找 `Exception`、`Error`、`FATAL`，以及退出前的最后一条业务日志。
- 插件报错：注意 `Caused by` 链，根因通常在最后一层。
- 配置问题：`server.properties` 与实际监听端口不一致是常见原因。

## 4. 结论怎么写
- 明确写出：时间窗、来源（实例/节点）、命中的原文行。
- 没有命中时也必须说明「在哪个范围、用了什么条件、没有命中」，
  而不是笼统地说「日志正常」。
- 日志里可能含玩家 ID、IP，输出时按需脱敏，不要整段贴出。
