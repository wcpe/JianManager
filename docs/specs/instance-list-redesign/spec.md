# 功能规格：实例列表页重设计（1000+ 实例）

> 状态：开发中（已通过审核，首批实现落地）　·　关联 PRD：FR-133、FR-137、FR-235、FR-244　·　依赖：FR-247

## 1. 背景与目标

FR-247 已提供实例服务端分页搜索与聚合地基，但前端实例页仍主要依赖 `GET /instances` 全量数组。FR-235 要面向 1000+ 实例重设计列表页；FR-137 要补搜索/排序/筛选吸顶/分组单表；FR-133 要处理实例导航搜索与 a11y；FR-244 要统一动画体验。

## 2. 需求

- `/instances` 首屏不再全量拉取 1000+ 实例。
- 搜索、筛选、排序、分页状态进入 URL。
- 卡片视图与列表视图都使用服务端分页数据。
- 分组视图采用单表或分组虚拟渲染，不重复整套表头。
- 筛选工具条 sticky 且可折叠。
- 返回/前进恢复筛选、排序、视图与滚动位置。
- 动画使用统一 token，不造成侧栏或主工作区掉帧。
- 移动端不横向翻屏。

范围外：

- 恢复 1000+ 常驻侧栏实例树。
- 前端假分页。
- 新增虚拟列表第三方依赖。

## 3. 设计

### 3.1 数据源

实例列表页使用：

- `GET /api/v1/instances/search`
- `GET /api/v1/instances/aggregate`

旧 `useInstances()` 保留给尚未迁移的页面，但 `/instances` 页面不再依赖它作为主数据源。

mock 模式必须同步补齐同名 MSW 端点：

- `GET /instances/search`：支持 `q/status/nodeId/role/networkId/env/tag/sort/order/page/pageSize`，返回 `{items,total,page,pageSize}`。
- `GET /instances/aggregate`：与后端聚合结构一致，至少返回 `total/byStatus/byNode/byRole`。
- `/instances` 页面 Playwright 验收需拦截网络请求，断言首屏不再请求裸数组 `GET /instances`。

### 3.2 URL 状态

URL query 草案：

```text
?q=hub&status=RUNNING&nodeId=1&role=backend&networkId=2&env=prod&tag=survival&sort=name&order=asc&page=1&pageSize=50&view=card&groupBy=node
```

### 3.3 FR-133 边界

根据 ADR-055，侧栏不承载 1000+ 常驻实例树。FR-133 调整为：

- 提供轻量实例搜索入口或当前实例导航辅助。
- 保留空态 CTA 和 a11y。
- 不在侧栏渲染全量实例树。

### 3.4 动画

FR-244 增量目标：

- 统一 `--motion-*` token。
- 路由切换、筛选折叠、Dialog、侧栏、移动抽屉使用同一缓动/时长。
- benchmark 断言动画不触发主内容逐帧 resize。

## 7. 默认卡片、指标与整体状态概览（2026-11-12）

### 7.1 展示约定

- `/instances` 默认卡片；`view=list` 显式恢复列表，切回卡片时移除默认参数。搜索、筛选、分组、分页和保存视图继续由 URL 恢复。
- 卡片分别展示节点名与节点 `host` + 实例 `serverPort`。IPv6 使用方括号；未知 IP、端口 0 分别显示未知或未分配，不把节点桥接端口或默认 25565 当作已知游戏端口。
- 已挂载的运行卡复用实时指标查询。CPU、内存缺测为 `--`，合法零值照常展示；内存为已用/上限，无上限不画虚假占比。人数展示当前/最大，TPS 依探针可用位决定，代理不展示 TPS；缺少来源时给出明确提示。
- 正常卡不保留空白异常槽，异常摘要和徽章有界；虚拟卡片行高 312px、间隙 8px、行盒 304px，与分组管理器共用，确保地址和底部操作完整。

### 7.2 概览统计范围

顶部状态分布图复用现有范围聚合，与四张状态卡一致：所选节点/群组/环境/标签范围，状态图不随状态细筛选或搜索词缩小；“活动中”包括运行、启动和停止过渡态。图表默认展开，可折叠。

指标区复用当前页既有批量历史序列，展示近一小时有效末次采样及覆盖台数；CPU/TPS 为已测样本均值、堆内存/后端人数为已测样本合计，停服和缺测不计，代理人数不重复计数。既有历史查询最多覆盖 50 个目标，页面明确表达覆盖，不将局部数据冒充全平台实时总量，也不为图表新增逐实例请求。卡片的实时进程内存与这里的堆内存历史口径分别标注。

### 7.3 托管探针实时接线

托管模式的推送快照由实时 RPC 与心跳共享读取；gRPC Server 经主进程注入读取依赖，不反向依赖 heartbeat 包。复用既有存储的存在/作废与缺项语义：探针会话断开或实例下线经 `Forget` 作废，没有快照时仍走既有 HTTP 探针 / SLP / Query 回退，不把不可用的 TPS 或人数伪造为零。现有存储不按快照年龄自动过期，本轮不新增 TTL 策略，也不新增 RPC 字段、HTTP 端点或数据库结构。

### 7.4 回归与用户复验

覆盖默认卡片/列表 URL 往返、分页/分组/启停确认、实际指标 API 注入、缺测与真实零、IPv6/未分配端口，以及概览样本覆盖/代理去重。浏览器检查长名称/异常提示、宽窄屏与操作区可见性；托管快照接线以快照命中/作废后回退/缺失/跨实例隔离回归验证。界面更新部署到开发环境供用户复验，不据此声称生产或长期稳定性验收。

本轮开发验证：服务器相关 9 个 DOM 测试文件共 78 项通过，Worker gRPC 整包及定向 race 通过，前端生产构建与相关 lint、Go vet 和文档门禁通过。开发入口实测 1516/1024/768/390px 下卡片内容与底部操作完整，无页面横溢；中英文案通过。运行态四指标与长内容使用浏览器读请求样本验证，未改动真实实例配置或启动进程。开发环境现有两台实例保持停止、端口未分配，节点身份、新心跳、实时 RPC 与日志服务健康复核通过。重连初期实例规格尚未重推时曾短暂返回指标 503，日志确认重推完成后两台实例接口均恢复正常；不将此启动窗口或运行态样本冒充持续真机运行验收。
