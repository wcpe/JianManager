# 功能规格：实例日志浏览器端实时流式跟随（FR-559）

- 状态：✅ 已交付@v0.24.0（开发版，联合验收通过）
- 关联 PRD：FR-559
- 依赖：FR-557 的实例日志结果模型、固定视口与原生选择行为
- 决策：[ADR-110：实例原生尾流桥](../../adr/110-native-instance-log-tail-stream.md)

## 1. 目标

把 Worker 已有的日志 Tail server-stream 通过 Control Plane 安全桥接到浏览器，让实例日志页面在不刷新、不跳布局的情况下显示新事件，同时允许暂停回看和恢复跟随。

## 2. 数据与连接边界

- 浏览器只连接 Control Plane；Control Plane 按当前用户、Query View 和授权范围创建 Worker Tail 请求。
- 节点/平台普通文本日志继续使用有限窗口刷新，不接入本流式 VL 桥。
- 初始历史窗口与实时事件使用同一筛选表达式和实例授权范围。
- 跨多个流只保证现有契约允许的流内顺序；不得对跨流事件宣称严格全局排序。

## 3. 连接状态

- `idle`：未开始实时跟随。
- `connecting`：正在建立查询连接。
- `live`：持续接收事件。
- `paused`：用户主动暂停或正在回看，连接可按策略取消/保留，但不得继续强制滚动。
- `reconnecting`：断线后按退避策略重连。
- `stopped`：用户停止或筛选条件改变，旧连接必须取消。
- `unsupported/error`：旧 Worker、不支持的查询能力或权限/预算错误，明确提示并可回退到轮询。

## 4. 资源治理

1. 每个浏览器连接有行数、字节数、缓冲区和最长运行时间上限。
2. 慢消费者触发丢弃/暂停/断开中的一种明确策略，并向用户显示状态；不得无限积压内存。
3. 浏览器关闭、路由离开、筛选变化、用户停止和 HTTP 断开都必须向 CP、Worker 和 VL 传播取消。
4. 重连必须带当前查询身份；不能把旧 View 的事件追加到新筛选结果。
5. 旧 Worker 或不支持 Tail 的节点回退轮询，回退原因可见。

## 5. 验收标准

- 真 VictoriaLogs + 真 Worker + CP + Chromium 环境中，持续写入实例日志能在浏览器实时出现。
- 点击暂停后新增事件不打断滚动位置和原生文本选区；恢复后只接收当前查询身份的事件。
- 断开网络后显示重连状态，恢复后能继续；切换筛选/实例/页签会取消旧连接且无旧事件串入。
- 触发行数/字节/时间预算和慢消费者上限时，页面显示明确原因，服务端资源最终释放。
- 权限撤销、Worker 不支持、VL 不可用、HTTP 取消分别有自动化覆盖和至少一次真机验证。

## 6. 非目标

不把节点/平台文件日志改造成 VL 流式数据面；不提供跨流严格全局顺序、无限历史回放或任意客户端直连 VL。

## 7. 实施与验收记录（2026-11-12，v0.24.0 开发版）

- 新 RPC `LogTailLive` 独立于旧单轮 `LogTail`；真实读取 VL 原生 tail。浏览器通过 CP Bearer SSE 接收 `ready/event/heartbeat/error`，不使用 URL JWT。CP/Worker 协议版本已统一为 `log-query/1`；真实 CP adapter→gRPC→Worker→VL HTTP 回归先复现原错字导致的 Unsupported，再验证修复、结构化字段与取消。
- 会话最多 45 秒、10000 行、8 MiB、8 个 Worker；队列 64 条、单事件 64 KiB。每 2 秒复核权限，受 token 到期与更小请求预算限制；高级订阅不再继承历史页默认 100 行限制。异常重连最多 6 次，预先发送 ready 不能重置失败上限；正常会话到期允许新建连接。
- **部署版 Chromium 真链通过**：向开发实例实际文件追加带日期的日志，经 tailer、真实受管 VL、反向 RPC、CP SSE 到内嵌页面；正常与恢复共 2 次原生订阅、GET tail 请求为 0。暂停期间由独立 SSE 确认新行真实已进入数据面，页面保持原样；原生跨行选区复制 269 字符一致。显式恢复仅清除本窗口选区、回到顶部，原有行 DOM 保留并收到新事件。全程页脚位置稳定、浏览器错误为 0。
- **真实撤权通过**：唯一临时账户经官方用户/RBAC 接口授权，已有 ready、heartbeat 和 12 条 event 后删除该主体，约 2000ms 收到 `FORBIDDEN`，随后自然 EOF，错误后事件为 0。临时主体与预探账户均已删除，GET 404、精确用户名查询为 0；既有管理员身份与权限不变，未发送邮件、未操作数据库或伪造 JWT。
- **真实故障与取消**：官方停止开发受管 VL 后，SSE 返回 `STREAM_UNAVAILABLE` 并 EOF；恢复后的正常流与取消后复开各收到 ready、heartbeat 和 12 条 event、零错误，客户端读取线程取消后退出。旧能力 Unsupported 的可见轮询回退在真实混版诊断中观察到，撤权和旧连接迟到回调不污染新范围另有主页面回归。
- **受管恢复修复**：故障验收发现启动 RPC 的短 ctx 曾终止刚启动的长驻 VL。现调用 ctx 只限制启动检查/观察，成功启动进程归 Supervisor Stop/StopAll 管理；预取消不 spawn，观察取消有界清理并保留错误链，StopAll 与在途 Start 串行回收。真实子进程与批准 VL 随机端口/临时目录验证请求结束后仍健康，StopAll 后 Wait/diagnostics 完成、PID 消失且端口可重新绑定；全包与 race 通过。
- **官方停启修复后复验通过**：仅执行一次开发节点 `hot/stop` 与一次 finally `hot/start`，均 HTTP 202 且无错误。停止达到 STOPPED/PID0，SSE 以 `STREAM_UNAVAILABLE` 结束；启动 RPC 返回后 9 次观测、18 秒内始终为同一 PID/启动身份，最终 20.039 秒仍 RUNNING/health=true。正常 SSE 收到 ready、9 heartbeat、27 event，复开收到 ready、heartbeat、9 event，均无错误；两次取消读取线程释放，分别观察到一条至开发 VL 的活动连接消失。控制审计均成功、未终态任务为 0，未新增主体或修改既有管理员。进程健康与分区 query-ready 仍分别呈现，本记录不把 health 当作分区恢复证明。
- **治理覆盖**：HTTP→Worker→VL 取消、权限撤销、来源前缀隔离、旧 Worker/CP 不支持、字节/行数/会话/慢消费者上限、缓冲和重试释放均有自动化测试；浏览器手动暂停、原生选择后恢复、范围切换、迟到回调与 429 回退另有集成回归。

10 秒回放只尽力而为，可能缺行或重复；连接成功和少量样本不代表完整历史。上述结果不宣称跨流严格全局排序、生产部署或长期压力稳定性。
