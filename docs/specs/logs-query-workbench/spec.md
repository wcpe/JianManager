# 功能规格：实例日志检索分析与字段探索（FR-557）

- 状态：✅ 已交付@v0.24.0（开发版，联合验收通过）
- 关联 PRD：FR-557
- 依赖：既有日志联邦 Query View、Search、Stats、Facets、Fields、Streams 与 stream-field 查询链路

## 1. 目标

把 VictoriaLogs 已存在的只读检索能力接入日志中心：在同一授权范围、同一时间范围和同一 Query View 下，同时展示日志列表、全窗口时间分布、级别/来源聚合、字段与流探索，并允许从字段/流追加筛选。

## 2. 数据边界

- 仅实例日志使用本规格的 VL 能力。
- 节点日志和平台日志仍是普通文本文件尾部窗口，不参与 VL 字段统计、全量总数或历史分页。
- 浏览器不直连 Worker 或 VictoriaLogs；所有请求经过 Control Plane 授权与反向隧道。
- 列表、统计、字段、流和导出必须绑定同一 Query View 身份；View 失效时显式提示并重新查询，不静默复用旧结果。

## 3. 功能范围

1. 全时间窗日志量：使用既有 Stats `timeBucket`，按时间范围自动选择有限桶数，显示 count，并保留 partial/truncated/unsupported 状态。
2. 聚合分析：级别、来源、流和受支持的数值字段聚合；字段不支持数值聚合时显示原因。
3. Fields：默认保留受控维度策略，工作台以 `explore=true` 在固定授权 View/Filter/有限时间窗内发现字段；候选由匹配行非空计数证实。探索总预算 1 MiB / 5 秒 / 16 次物理读取、最多 256 个字段；单字段常见值最多 20 项，保留明确截断/质量状态。新端响应 `explore_applied`，旧端缺确认不得显示假探索。支持点号、连字符名称的安全引用。
4. Streams：展示 `log_source_id`、stream、命中数及完整性；`complete=false` 时不得把 hits 当作精确值。
5. Stream fields：消费流字段名和值，用于来源/流的细化筛选。
6. 日志详情：展开单条日志时显示结构化字段、原始消息、来源名称、流和时间。

## 4. 验收标准

- 列表与时间图的 `from/to`、授权目标、过滤条件和 `viewId` 完全一致。
- 切换字段/流筛选会生成新的筛选身份；旧查询结果不可冒充新筛选结果。
- 全窗口时间图不使用当前页时间戳伪造；无时序结果或聚合失败时显示明确状态。
- 真实 VictoriaLogs v1.52.0 环境完成 Search、Stats time bucket、Fields、Facets、Streams、stream-field、分页和导出回归。
- 非平台管理员的授权范围、节点查询拒绝、空授权拒绝和跨主体 View 复用保护保持有效。
- 平台管理员在实例页或全部日志只选择节点时，VL 子查询展开为该节点实例目标；节点目标不冒充实例目标，不带入其他节点实例。`source=worker` 的兼容 VL 查询仍只读节点目标；无实例节点不得因空集合退回全平台授权。
- 实机复验必须包含开发 Worker 重启后持续产生的新行：来源时区明确、事件 UTC 时间和 Catalog UTC 日一致，默认最近一小时非空；资源水位拒绝与无日志必须区分。
- 查询超时、预算超限、429、字段不存在、Worker 不支持和 VL 不可用分别有可行动提示，不返回空成功。
- 管理员看到平台、节点、实例、全部四个独立页签；平台/节点只请求普通文本尾部，实例继续使用既有 VL 协议，普通用户不能借 URL 打开进程日志或混合汇总。
- 全部日志汇总有限的文本尾部与实例当前页；保留每源读取限制、截断、离线/超限和失败状态，未知时间不伪造，相同正文跨来源不误去重。范围切换取消旧请求，迟到结果不混入新窗口，原生选区冻结正文。
- 文本和汇总导出只包含当前筛选可见行，NDJSON 元信息明确当前窗口与非完整历史；实例历史导出仍经过原服务端授权、覆盖与质量门禁。

## 5. 非目标

本规格不引入日志删除、retention 管理、租户管理、保存搜索会话、仪表盘编排或 AI 日志分析。

## 6. 实施与验收记录（2026-11-12，v0.24.0 开发版）

- **数据边界**：实例使用 VL；节点/平台使用独立文件工作台，窗口 50/100/200 行且最多 64 KiB，搜索和级别只作用于已读窗口。节点必须显式选择，不把文件快照当完整历史。
- **固定视口与原生操作**：部署后的 Chromium 在 1024×768、1280×768、1536×900 三个视口，分别切换普通、LogsQL、跟随、暂停和平台文本，共 15 个状态。工具栏、状态和页脚位置保持一致，根页面滚动量为 0。原生跨行选区及 Ctrl+C 剪贴板一致；后续事件不替换暂停时的行 DOM。四个洞察单元固定位置，来源数据晚到不会挤动时间图；窄屏保持横向滚动而不隐藏后排卡片。
- **真实多进程链**：开发 CP/Worker 与受管 VL v1.52.0，向授权实例写入 5 条带独立标识的记录后，用真实原生流确认可见，再复用同一绝对时间窗、筛选与 View 验证 Search、Fields、Facets、Streams、stream-field 名/值、1 分钟 Stats 桶及导出，均得到对应 5 条数据。Search 与 Live 均保留 `trace_id`。数值输入含 10、20、非数值、缺失、−2；有效样本 3、sum=28、min=−2、max=20、avg=28/3。
- **历史字段与页边界**：隔离真实 VL 验证保留 canonical top-K 后的有界全字段补查；Single/Merged 的 304 条同戳组跨两页不丢不重。跨源、错误代次、越水位、过滤外和时间外副本不能提供补查字段；转义身份和共享字节/物理读取预算均有回归。
- **字段探索**：真实 CP adapter→gRPC→Worker→VL 验证默认白名单不变、显式探索执行确认、旧端缺确认拒绝。VL 块级字段候选必须在同授权范围、代次、水位、筛选与时间窗内证明非空；高基数结果明确截断/partial。`http.status_code`、`trace-id` 的字段发现、精确分面、包含/排除和数值分组全部通过。1 MiB 硬字节、5 秒、16 次物理请求及父账本只收紧均有实测回归。
- **主界面联合验收**：中文亮色、英文暗色分别验证历史详情、字段常见值、`latency_ms` 按 stream 和 1m 的数值表、同 View 绑定、包含动作修改草稿后禁导出、应用筛选及页脚稳定，浏览器错误为 0。
- **资源拒绝与恢复**：开发文件系统超过 80% 水位时，导出返回明确 incomplete，未下载伪完整文件；清理可再生 Go 构建缓存后水位降至 79%，不修改保护阈值、不删业务数据，重新验证导出为 5 行 NDJSON。
- **自动化**：最终前端日志范围 23 文件、282 用例通过；相关 Go 查询、适配、RPC、VL、协调、HTTP 路由与中间件回归通过。路由全包一次出现无关快照测试 TempDir 清理竞态，单项和最终全包复跑均通过。隔离真实 VL 与预算/取消、混版不支持、429 保留/恢复/范围隔离测试分别通过。

本记录只覆盖上述开发环境、数据样本和浏览器状态，不代表生产部署、无限历史性能或长期稳定性承诺。一次性探针与输出不入库。

## 7. 四类视图与窗口汇总补充验收（2026-11-12）

- 管理员页面拆为平台、节点、实例、全部四个独立页签；默认实例页签的后端协议仍为 `view=node_instance&source=instance`。节点/平台只读取普通文本，实例保留原 VL 查询与服务端导出；旧节点来源深链兼容，普通用户不能通过 URL 打开进程日志或汇总。
- 全部日志默认合并平台尾部、最多 4 个在线节点尾部及实例当前页。文本每源 100 行、实例当前页 100 行；离线、超限、读取失败、截断和覆盖未确认分别可见。范围变化取消旧传输，迟到响应不混入新范围；原生选区冻结正文；未知时间置后且保留原文，相同内容跨来源不被误去重。
- 自动化：日志范围 28 文件 / 317 用例通过；最后补充的来源身份映射与下载专项连同 All 窗口回归 8 项、快照导出 2 项通过。TypeScript、相关 ESLint、Web 构建、CP 嵌入构建和日志中心 Playwright 主流程通过。
- 联合开发候选部署到 `<dev-root>`，在真实 CP、Worker、VL 与 Chromium 上复验中文亮色、英文暗色以及 1024×768、1280×768、1536×900 三种视口，共 24 个页签状态。实例每页 100 行，平台/节点各 200 行最近文本，全部日志合并三类共 300 行；根页面横纵滚动量为 0，页脚在屏内，浏览器错误为 0。

本补充记录只覆盖有限已加载窗口和上述开发环境；不代表平台/节点文本拥有历史检索，也不代表混合窗口为完整历史。生产环境不在本轮部署范围内。

## 8. 默认时间窗与节点筛选回归修复（2026-11-13）

- **现场原因**：开发根文件系统达到 90% 查询暂停水位；资源恢复后，Worker 缺少来源时区配置，按 UTC 解释东八区的 `[HH:MM:SS]` 日志，启动时又沿用了前一个 UTC 日期。仅扩大查询窗口不能解决新日志时间错误。
- **运行修复**：仅清理确认无使用的可再生构建缓存，保留保护阈值、业务/VL 数据及 registry；开发 Worker 显式配置 `log_ingest.time_zone: Asia/Shanghai` 后重启生效。最近一小时由 0 行恢复为 100 行，新行 UTC 时刻与原始时刻换算一致，位点继续前进；已有错误时间戳不自动重写。
- **代码缺口**：管理员的 `nodeId + source=instance` 原先被收敛为节点自身目标，再与 `inst:` 过滤相交，普通实例页只选节点以及全部日志继承节点筛选都会返回空。目标解析现在经可信实例目录展开同节点实例，节点来源仍只查询节点；兼容聚合保留节点与其所属实例。无实例节点不把空授权变成全平台通配，非管理员节点全量查询仍拒绝。
- **自动化补强**：真实 Router/DB、尊重授权入参的 resolver 与按请求目标返回同源行的 Worker 替身，对门面与 Search 各覆盖实例来源、节点来源、省略来源、全部来源、空节点、普通成员拒绝。初次为 6 红/6 绿，修复后 12 个场景全绿；另补目录依赖缺失、读取失败的拒绝及节点来源不依赖实例目录三项回归。相关日志/权限/查询 HTTP 回归通过。
- **部署边界**：只更新开发 CP 的目标解析与装配；Worker 保留已部署二进制，仅通过运行配置恢复时区。实例与生产进程启动身份保持，未降低资源或导出门禁。
- **实际地址复验**：在 `http://example.com:18080/logs` 用真实 Chromium 打开默认最近一小时，显示 100 行实例日志，最新行距查询约 2 秒；只选择节点后仍显示 100 行实例日志。平台/节点各显示 200 行文本，节点选择切入全部后仍合并三源 300 行（其中 VL 100 行），浏览器错误为 0。部署后再次核对 13 个受保护进程身份、采集位点单调前进及候选二进制一致。
