# 功能规格：受控用户创建与邮箱邀请

> 状态：开发中 · 关联 PRD：FR-405、FIX-公开注册 · 分支：dev

## 1. 背景与目标

`POST /api/v1/auth/register` 当前允许匿名创建可登录成员，管理端创建用户也错误依赖该公开入口。该功能同时修复公开注册漏洞，并提供两种受控入驻方式：平台管理员直接创建，以及通过一次性邮件邀请自助设置用户名和密码。

## 2. 需求（要什么）

- 仅平台管理员可直接创建用户，可在一次请求内指定用户名、初始密码、角色与状态。
- 仅平台管理员可创建、查看和撤销邀请；邀请只能创建 `RoleMember`，有效期固定为 7 天且仅可使用一次。
- 管理员填写受邀邮箱后，系统使用独立 SMTP 设置发送邀请邮件；邮件中的链接由平台统一的公共基址生成，受邀者在页面自行设置用户名和密码。
- SMTP 未配置或投递失败时，邀请仍创建成功，并仅在本次创建响应中返回一次性链接供管理员手动发送。
- 关闭公开注册；初始化 `POST /setup`、登录和刷新令牌行为保持不变。

范围内：邀请邮件、一次性令牌、管理员直建、邀请接受页、SMTP 与公共基址配置、审计与测试。

不做：邮箱作为用户资料或登录名、找回密码、邮件模板编辑、邮件队列/自动重试、自动加入用户组、邀请授予组管理员或平台管理员。

## 3. 设计（怎么做）

- 新增 `user_invitations` 加性表：只保存 SHA-256 令牌哈希与前缀，不保存明文令牌；保存受邀邮箱、有效期、签发人、使用/撤销状态、邮件投递状态。既有用户表与登录令牌无迁移破坏。
- 管理员直建使用受保护的 `POST /users`；创建与角色赋值同一事务完成，替代旧的“公开注册→查询→改角色”两步流程。
- 公开端只保留 `POST /auth/invitations/accept`。它在同一事务内以条件更新原子消费未过期、未撤销、未使用的邀请并创建 active member；竞态仅允许一个请求成功。失效、撤销、已用和伪造令牌统一返回 `INVITATION_INVALID`，不泄露状态。
- 平台统一公共基址为 `platform.public_base_url`，接受完整 `http://` 或 `https://` 地址，不接受查询参数或片段，不得由请求 Host 或转发头推断。邀请链接形如 `<platform.public_base_url>/invite#<token>`；后续所有需要生成绝对域名链接的功能必须复用此设置。令牌置于 URL fragment，不随初次 HTTP 请求、反向代理访问日志或 Referer 发送；前端邀请页读取 fragment 后才提交接受请求。
- SMTP 配置为系统设置中的邀请邮件分类：`invite.smtp.host`、`invite.smtp.port`、`invite.smtp.username`、`invite.smtp.password`、`invite.smtp.from`。密码只能保存 `${ENV_VAR}` 引用，读取接口仅返回脱敏状态。复用现有 SMTP 的 STARTTLS/465 TLS 传输能力，不复用告警通道或其静态收件人。
- 所有邀请管理操作写审计；审计、日志、列表和错误响应均不得包含明文邀请令牌、密码、SMTP 密码或完整邮件正文。

## 5. 验收标准

- 未认证请求不能通过旧 `/auth/register` 创建或登录新账号；首次 `/setup` 仍可创建初始管理员。
- 平台管理员可通过一次 `POST /users` 创建任意现有角色；成员和组管理员调用该端点被拒绝。
- 邀请仅允许创建组成员；有效邀请可创建并登录一个成员；并发接受同一邀请仅一个成功；过期、撤销、已用、伪造令牌均不创建用户且返回同一错误。
- 用户名冲突不消耗邀请；数据库、审计和 API 列表均不出现明文令牌、密码或 SMTP 密码。
- 已配置 SMTP 时，测试 SMTP 收到含已配置公共基址（HTTP 或 HTTPS）的链接；未配置或投递失败时管理员仍可一次性取得手动发送链接。
- 真机验收：管理员配置 SMTP 与公共基址，向测试邮箱发出邀请；受邀者打开邮件链接、设置账号并登录；管理员撤销的链接不可使用。该项需用户确认。

## 6. 风险 / 待定

- 邮件送达依赖部署环境 SMTP 和 DNS；本期以同步投递和清晰失败状态为准，不引入后台队列。
- 邀请链接必须配置公共基址；未配置时禁止发送邮件，避免从 Host/X-Forwarded-* 推断地址造成链接注入。允许 HTTP 是为无 TLS 的自托管内网部署；公开互联网部署仍应使用 HTTPS。
- 此功能新增模型、公开接受接口、管理员接口和平台设置，须经本规格与 API 规格审核后才能实现。
