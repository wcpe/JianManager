# 控制台日志视图重做（FR-415 / FR-418 / FR-419）

- 状态：🔨 开发中
- 关联：ADR-086（输出/输入分离）、ADR-067（会话保活）、ADR-081（终端经 CP 中转）、FR-345（停机日志回放）、FR-150（日志中心）
- 目标版本：v0.22.0

## 1. 行模型与解析器（FR-415 核心，三条 FR 共用）

### 1.1 行模型

```ts
type LogKind = 'log' | 'command' | 'stack-frame' | 'stack-cause' | 'system'

interface LogLine {
  seq: number            // 单调递增，环形缓冲内唯一；选区与定位一律用它，不用数组下标
  ts?: string            // 从行首解析出的时间（形如 [09:12:13]），解析失败则 undefined
  level?: 'INFO' | 'WARN' | 'ERROR' | 'DEBUG' | 'TRACE'
  source?: string        // [Server] / [Paper] / 插件名
  body: string           // 去掉已解析前缀后的正文（含 ANSI 段）
  raw: string            // 原始整行，复制与导出一律用它
  kind: LogKind
  stackOf?: number       // stack-frame / stack-cause 指向其异常头行的 seq
}
```

**`raw` 与 `body` 都保留**：展示用 `body`（前缀已拆成独立列），复制用 `raw`（用户要的是原始日志，
不是我们重排过的）。

### 1.2 解析规则（保守优先）

按顺序尝试，**任一步不匹配即降级为 `kind:'log'` 且字段留空——绝不猜**：

1. **时间 + 级别前缀**：`[HH:MM:SS] [<thread>/<LEVEL>]:` （MC 原生 / Paper 格式）或 `[HH:MM:SS INFO]:`
2. **来源**：正文开头的 `[Xxx]` 取作 `source`
3. **堆栈帧**：`\tat <fqcn>(<file>:<line>)` 或 `\t... N more` → `kind:'stack-frame'`
4. **Caused by**：`Caused by: <exception>` → `kind:'stack-cause'`
5. **异常头**：正文匹配 `<fqcn>(Exception|Error|Throwable): ...` 或其后紧跟 stack-frame → 该行为异常头

**级别兜底**：解析不出级别时，stderr 流记 `ERROR`、stdout 流记 `INFO`（与后端 `log_ingest` 现有推断一致，
不引入第二套规则）。

**时间继承（lastTs，2026-09-07 增补）**：Paper 多行日志（如 spark 告警）的续行没有 `[HH:MM:SS]` 前缀，
若时间列整行空白会破坏扫读。规则：`ts = prefix.ts ?? state.lastTs`——无时间前缀的日志行**继承最近一次
解析到的时间**（含跨 chunk：WS 分包任意切行，parser 实例随行缓冲会话级存活）。边界：

1. **命令回显 / 系统提示经 `synthesize` 合成时重置 state**（连带清 lastTs）——合成事件是时间线上的
   新锚点，其后的无前缀行不再继承回显前的时间；
2. **历史回溯（DB 行）每次新建独立 parser**，实时缓冲、不同回溯批次之间互不污染；
3. 无任何继承源（如会话首行即无前缀）时 `ts` 仍为 undefined，时间列留空；
4. **绝不把到达时刻等猜测值写入 `ts`**（曾短暂引入 `~到达时刻` 兜底，因在 06:30 的日志流里出现
   08:29 的"未来时间"造成错位观感而回退，以继承方案取代）。

### 1.3 ANSI

只处理 SGR（`ESC[...m`）：前景 30-37/90-97、背景 40-47/100-107、粗体 1、重置 0/39/49。
**其他转义序列一律吞掉不渲染**（包括光标移动、清屏、`\r` 回车覆盖）——不做终端仿真（ADR-086 代价 5）。

## 2. FR-415：输出区与命令栏

### 2.1 输出区

- 虚拟列表，固定行高，overscan 上下各 12 行
- 环形缓冲 5000 行；溢出丢最旧，并在顶部留一条"更早日志需回溯"的锚点（FR-419 据此加载）
- 自动滚底；用户手动上滚即暂停自动滚底并显示"跳到底部（N 条新）"浮标，点击或滚到底恢复
- 只读：不接键盘输入
- **`terminalSessionManager` 的保活语义不变**（ADR-067）：行缓冲与 WS 连接常驻管理器，
  组件卸载只 detach 渲染层，页签隐藏/实例切换不断连

### 2.2 命令栏

- 原生 `<input>`，`Enter` 提交整行（`data: line`，**不补 `\n`**），提交后清空
  —— Worker 三种启动策略写 stdin 时各自补行尾（`direct` 用 `fmt.Fprintln`、`daemon`/`docker`
  拼 `command + "\n"`，见 `internal/worker/process/`），前端再补会多送一条空命令
- 提交的命令以 `kind:'command'` 回显进输出区（本地回显，不等服务端）
- 非 RUNNING 态：`disabled` + 一行原因 + 直达动作（停止态给「启动实例」按钮）
- **不再监听 xterm 的 `onData`**，不再手工回显/退格

### 2.3 验收

- [ ] `←` `→` `Home` `End` `Ctrl+A` `Ctrl+E` `Ctrl+W` `Ctrl+U` 全部标准语义
- [ ] 中文输入法输入「说 大家好」：无乱码、无重复回显、组合过程不被打断
- [ ] `Ctrl+V` 粘贴单行正常（HTTP 非安全上下文下也要能用，靠原生 paste 事件而非 `readText()`）
- [ ] 灌 10000 行滚动 ≥50fps（Performance 面板实测，贴数字）
- [ ] ANSI 着色与旧 xterm 渲染肉眼一致；构造未知转义序列不产生可见垃圾字符
- [ ] 手动上滚 → 自动滚底暂停 + 浮标出现并计数；点浮标回到底部
- [ ] 停机态输入禁用 + 原因 + 「启动实例」可点
- [ ] 页签切走再切回、实例间切换：缓冲与连接不丢（ADR-067 回归）
- [ ] ✱ 真机复验一遍上述交互

## 3. FR-418：锚点选区与堆栈块

### 3.1 锚点选区

**问题**：虚拟列表只渲染可视行，原生跨行选区拖出屏幕即断（ADR-086 代价 2）。

**方案**：
- `mousedown` 记锚点 `seq`，`mousemove` 更新终点 `seq`，选中区间 = `[min, max]`
- 拖到视口上/下边缘触发**自动滚动**（边缘 32px 内，按距离加速），滚动中持续扩选
- 松手后文本**从行缓冲取**（按 `seq` 区间取 `raw`），不从 DOM 取
- `Shift+Click` 扩选、`Ctrl+A` 全选缓冲
- **同一行内不进入锚点模式**（`mousedown` 与 `mousemove` 在同一 `seq`）→ 交给原生字符级选区
- 选中后浮出工具条：复制 / 存为 .log / 只看这段（把区间当临时过滤器）/ 取消

**选区内核独立成模块**，供 FR-421 的键盘复制模式复用（同一套 `seq` 区间语义）。

### 3.2 堆栈块

- 解析器已标出 `stack-frame` / `stack-cause` 与其 `stackOf`
- 渲染时把异常头 + 其全部帧折叠为**一个块**，默认折叠，显示异常首行 + 「堆栈 N 行」
- 「复制整块」= 异常头 + 全部帧 + `Caused by` 链的 `raw` 拼接
- 级别过滤（FR-417）切 ERROR 时，**整块作为一个单位保留**，不能只剩头行
- 双击异常头 = 选中整块

### 3.3 验收

- [ ] 跨 500+ 行拖选（触发边缘自动滚动）松手后复制内容**完整无缺行**
- [ ] 单行内可字符级选取某个 UUID / 坐标
- [ ] `Ctrl+A` 全选缓冲；`Shift+Click` 扩选
- [ ] NPE 堆栈默认折叠为一行、点开展开、「复制整块」拿到异常头 + 全部帧 + Caused by
- [ ] 切 ERROR 过滤后堆栈块整块保留
- [ ] ✱ 真机在 HTTP 上下文下复制成功（走 `writeText` + execCommand 兜底）

## 4. FR-419：历史日志无限回溯

### 4.1 数据源分层（已核实现状）

| 层 | 范围 | 取法 |
|---|---|---|
| 内存环形缓冲 | 最新 5000 行 | 瞬时，无请求 |
| 数据库活日志 | 14 天 / 512MB（`LogStoreConfig`） | `/logs` 游标分页，已有 `idx_logs_instance_time` |
| 归档 NDJSON | 超保留期，`data/var/log/*.ndjson` | **本批不做**（YAGNI） |

日志是**全量实时落库**（`log_ingest.go` 异步缓冲批量 INSERT），不是只在崩溃时抓——回溯有数据源。

### 4.2 后端：游标分页

**现状问题**：`/logs` 是 OFFSET/LIMIT，按 `time DESC, id DESC` 排序。向上翻页期间有新日志涌入时，
offset 语义漂移 → **重复行或丢行**。

**改动**：新增游标参数，与现有 `page/pageSize` **并存不破坏调用方**（日志中心 `/logs` 页仍用页码）。

```
GET /api/v1/logs?...&cursor=<time>_<id>&limit=N
```

- `cursor` 为空 = 从最新开始；返回体新增 `nextCursor`（为 null 表示已到最早）
- 查询条件：`(time, id) < (cursorTime, cursorId)` 配合既有 `idx_logs_instance_time`
- `limit` 上限沿用现有 500

### 4.3 前端

- 滚到顶部触发加载更早一页，**保持滚动锚定**：未溢出时数据库接缝为会话开始；发生环形缓冲
  溢出后接缝推进到最早保留行的浏览器接收时刻，使会话内被挤掉的日志也能回补。DB 与 WS 在
  接缝附近的连续原文重叠去重（单条高频文案宁可保留，不冒险误删）。prepend 前记录锚点行的 offsetTop，
  prepend 后恢复，使视口不跳动（虚拟列表 prepend 的经典坑）。**接缝只在实例切换时重置**：
  同一实例内接缝随缓冲溢出前移不重置（DB 行不会消失，重置只会把已加载历史整体作废重拉）
- 顶部横幅标明**回溯到哪儿了 + 数据来自哪层**（内存 / 数据库）；到最早时明示「已是最早」而非静默停住
- **「跳到本次启动」**：在缓冲内向上找最近的 `Done (Xs)!` 或启动标记行并定位；缓冲内找不到则按时间条件查库
- **「跳到时间…」**：输入时间点直接定位
- 级别过滤在前端完整页上应用：异常的调用栈帧常以 stdout/INFO 落库，若把精确 `level` 参数带进
  查询会把帧丢掉；回溯页先完整取回，再由前端以「异常块整体保留」的语义过滤，不能为省流量
  牺牲 Java 堆栈的可读性

### 4.4 验收

- [ ] 滚到顶自动加载更早，**视口不跳动**
- [ ] 加载期间持续有新日志涌入，不出现重复行 / 丢行（游标生效；用 mock 高频推送构造）
- [ ] 「跳到本次启动」定位到启动完成行
- [ ] 「跳到时间…」定位到指定时刻附近
- [ ] 回溯到数据库边界时明示「已是最早」
- [ ] `/logs` 的现有页码调用方（日志中心）行为不变（回归）
- [ ] 后端游标查询有单测覆盖边界（空游标、末页、并发插入）
- [ ] ✱ 真机在有真实数据量的实例上回溯至少 3 页

## 5. 明确不做

- 归档 NDJSON 纳入 API 查询（14 天足够排障，超期去 `/logs` 页或直接看文件）
- 后端日志结构化落库（`Message` 仍存原始文本，解析在前端；后端结构化是独立议题）
- 全站立即移除 `@xterm/*` 依赖（遗留 `components/Terminal.tsx` 与其兼容测试仍在仓库；依赖清理另开 refactor）
- 终端仿真（光标移动、清屏、`\r` 原地覆盖一律不支持，见 ADR-086 代价 5）
- 跨行字符级选区（虚拟列表下不可靠；跨行一律行级）
- 输出区的可写化（输出区永远只读，输入只经命令栏）
