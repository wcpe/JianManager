# 实例界面布局重排（FR-422 / FR-423）

- 状态：🔨 开发中（FR-422），📋 计划（FR-423）
- 关联：FR-269（统一控制台）、FR-296/ADR-067（页签 keep-alive 与热缓存）、FR-412（顶栏瘦身）、FR-413（Tab 重组）
- 目标版本：v0.22.0

## 1. 问题（量测证据，1920×1030 视口）

| 病症 | 证据 |
|---|---|
| 等高栏 + 内容量悬殊 → 矮卡被撑高 | 概览「关注事项」卡高 229px，尾部死区 **159px（69%）**；「最近事件」死区 **97px（42%）** |
| 内容区高度写死，不跟视口 | 所有 Tab `document.scrollHeight === innerHeight`，内容从不撑满；文件配置底部空 **120px**、玩家 Tab **150px**；屏幕越大浪费越多 |
| 空态卡片占固定高度 | 「崩溃诊断」无数据时仍占 **88px** 说一句「暂无」 |
| 整页滚动导致顶栏滚出视野 | 内容超高时启停按钮与状态徽章一起滚掉 |
| 多层横栏叠加 | 文件配置：分段栏 + 导航栏 + 重复面包屑 + 工具栏 ≈ **160px**，叠加顶栏 160px 后只剩 710px 干活 |
| 同页宽度策略不统一 | 玩家 Tab 三个表格宽 1700 / 1700 / 460px；在线玩家的名字到操作按钮**视线横跨 1650px** |

## 2. FR-422：视口自适应骨架

### 2.1 骨架契约

```
Workspace 容器（isInstanceRoute）   overflow-hidden          ← 滚动不再发生在页面级
└─ 路由过渡容器                     flex h-full flex-col
   └─ InstanceConsolePage           flex h-full min-h-0 flex-col
      ├─ 失败/搭建横幅（条件）       flex-none
      ├─ 顶栏                       flex-none   （FR-412 瘦身后 ≤ 90px）
      ├─ Tab 栏                     flex-none
      └─ Tab 内容区                 flex-1 min-h-0   ← 吃掉全部剩余高度
         └─ 卡片                    overflow-auto     ← 滚动收口在此
```

**不变量**
- 顶栏与 Tab 栏**永不滚出视野**（启停按钮与状态徽章常驻可点）。
- Tab 内容区高度 = 视口 − 顶栏 − Tab 栏 − padding，**不设 `min-height` 下限**。
- 每个滚动容器必须同时有 `min-h-0`（否则 flex 子项不收缩、`overflow` 失效）。
- 作用域仅 `/^\/instances\/\d+/`；列表页、向导页与其他路由的滚动模型不变。

### 2.2 横栏合并（文件配置）

分段（文件/环境变量/配置引擎）→ 前进后退 → 面包屑 → 工具按钮，**合并为单条**卡片头横栏：
- 分段左对齐、工具按钮右对齐，面包屑占中间弹性空间并显示当前目录汇总（`/ · 15 项 · 63.8 MB`）。
- 面包屑只出现一次（现状输入框与下方各一份，重复）。
- 高频按钮（新建 / 上传 / 搜索）留明文，低频收进 `⋯`。

### 2.3 验收

- [ ] 无横幅时顶栏 DevTools 实测 ≤ 90px（FR-412 配套）
- [ ] 9 个 Tab 逐个量测：卡片尾部死区 = 0，内容区高度 = 视口 − 顶栏 − Tab 栏 − padding
- [ ] `document.scrollHeight === innerHeight`（页面不整体滚动）
- [ ] 内容超高时**卡片内部**出现滚动条，顶栏与 Tab 栏保持可见
- [ ] 窗口从 1030px 拉高到 1400px，新增高度全部进入内容区（不产生底部留白）
- [ ] 实例列表页 / 向导页 / 其他路由滚动行为无变化（回归）
- [ ] 文件配置横栏由 4 条压到 1 条，同屏文件可见行数从 3 提升到 ≥ 12
- [ ] ✱ 真机（FR-277 主机）Chrome 与 Firefox 各验一遍，确认无横向滚动条与内容截断

## 3. FR-423：分栏重排与空态收缩

### 3.1 分栏原则

**按内容天然宽度需求分栏，不按数量均分。**

| Tab | 分栏 | 依据 |
|---|---|---|
| 概览 | 左 62%（图表 + 日志）/ 右 38%（动态与告警） | 日志需要横向空间放消息全文；事件流是窄列表 |
| 玩家 | 左 38%（在线玩家 + 白名单）/ 右 62%（封禁记录） | 前两者是 2 列窄内容，后者是 7 列宽表 |
| 插件 | 左 62%（插件表）/ 右 38%（需关注 + 上传 + 市场） | 列表 + 详情 |
| 业务 | **左右 50:50**（能力清单 / 下发面板） | 两侧都是工作区：左要横向铺域块，右的返回 JSON 怕横向滚 |
| Bot | 左 62%（Bot 表）/ 右 38%（运行概览） | 列表 + 详情 |
| 备份定时 | 左 62%（备份记录）/ 右 38%（定时任务） | 列表 + 详情 |
| 监控 | **不分栏**（图表两行 + 世界统计段） | 图表要等宽并排，分栏会把曲线压窄 |

实施时发现的偏差（本表已修正）：初稿把「经济表 / 背包查询」列进业务栏、「压测 / 运行时」列进 Bot 栏，
但这些是独立卡片类型（`economy` / `inventory`）或 `/bots` 独立页的能力，本页签内并不存在——
初稿是照原型臆想的内容填的表，不是照代码。已按实际内容修正，未把它们搬进页签。

### 3.2 高度分配规则

- 栏内**内容驱动型卡**用 `flex-none`（在线玩家、白名单、定时任务、能力清单）——数据少时空白落在**栏位空隙**，而非撑坏卡片内部。
- 栏内**主列表卡**用 `flex-1 min-h-0`（封禁记录、插件表、备份记录）——多出的高度用来多显数据行。
- 横向并排的卡改 `items-start`，**矮卡不被高卡拉平**。
- 空态高度按内容走：`h-auto` 一行，不再占固定高度块。

### 3.3 概览三卡合流

「最近事件」+「关注事项」+「崩溃诊断」→ 单个 **「动态与告警」** 卡，同一条时间线按时间倒序混排：

- 数据源：`useLogs`（近期日志）+ `buildWatchItems()`（告警项）+ `useCrashSnapshots`（崩溃现场）。
- 行内元素：状态点（success/info/warning/danger/neutral）+ 主文案 + 次行（时间 + 补充信息）+ 悬停复制按钮。
- 告警项排在最前（无告警时显示一行「运行状态正常」并带持续时长）。
- 崩溃记录可展开看现场；无崩溃时并入流末尾一行灰字，不单独占卡。
- **保留 `CrashDiagnosticsCard` 组件**用于展开态渲染，不删除其现场解析逻辑。

### 3.4 验收

- [ ] 概览：三卡合流为一条流，卡内死区 = 0；有告警时告警在最前；无崩溃时末尾一行灰字
- [ ] 玩家：在线玩家与白名单改行卡片，**最长行宽 ≤ 700px**（名字到操作按钮视线距离）
- [ ] 六个分栏 Tab 逐个确认左右比例生效，窄屏（< 1100px）降级为单列纵向堆叠
- [ ] 内容驱动卡在数据为 1 条时高度贴合内容（不出现卡内大片空白）
- [ ] 主列表卡在数据超出时内部滚动，栏高不被撑破
- [ ] ✱ 真机对比改造前后同一实例、同一窗口尺寸的可见数据行数，逐 Tab 记录

## 4. 明确不做

- 不改其他路由（列表页 / 向导 / 超级工作台 / 导播台）的滚动与布局模型
- 不引入新的布局库（继续用 Tailwind flex/grid，不为此引 react-grid-layout）
- 不改数据层：本批只重排既有数据的呈现，不新增 API 调用（概览合流复用已有三个查询）
- 不做响应式断点的全面重设计，只保证窄屏降级为单列不破版
- 表格列宽治理归 FR-424，本 spec 不含
