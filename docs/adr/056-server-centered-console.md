# ADR-056: 服务器为中心的统一控制台

- **日期**: 2026-07-02
- **状态**: accepted
- **关联**: FR-269、FR-166、FR-167、FR-168、ADR-034、ADR-035

## 上下文

FR-166 已把实例工作区升级为可组合卡片画布，适合高级用户把终端、文件、监控、业务等功能自由拼装。该能力是差异化优势，但作为单服默认入口存在两个问题：

- 深链 `/instances/:id` 只触发打开画布，缺少稳定、可预期的详情页结构。
- 新用户需要先理解“添加卡片 / 预设 / 画布”，才能完成基础运维操作。

用户确认的新方向是：单台服务器有固定分区控制台，高频操作一进页即可看到；高级拼屏能力继续保留。

## 决策

`/instances/:id` 默认渲染 **服务器统一控制台**，而不是只进入可组合画布。

固定分区：

- 概览
- 控制台
- 文件配置
- 监控
- 玩家
- 插件
- 备份定时
- 业务
- Bot

服务器控制台顶部固定状态条展示运行态、节点、端口、在线玩家、TPS、MSPT，并提供启动 / 停止 / 重启 / 强杀 / 打开终端等操作。

可组合画布、超级工作台、导播台继续保留：

- 固定控制台 = 单台服务器默认入口。
- 超级工作台 / 导播台 = 多服拼屏和高级监看入口。
- 旧卡片内容组件可以在固定分区中复用，避免重写终端、文件、监控、插件、业务、Bot。

## 理由

- **默认路径更稳定**：URL 能直接展示可寻址的单服详情页。
- **降低学习成本**：用户不必先理解画布即可运维。
- **不损失高级能力**：画布仍服务跨服监控墙和导播场景。
- **复用现有投资**：`WorkspaceCardBody` 等卡片内容可作为分区内容复用。

## 后果

- `InstanceDetailPage` / `Workspace` 的 `/instances/:id` 路径需要接到服务器控制台组件。
- 列表点击服务器可以导航到 `/instances/:id`，也可以通过现有 store 打开同一控制台。
- FR-166 相关代码不删除，后续可提供“打开拼装视图”入口。

## 落地状态

截至 2026-07-05，本决策已随 FR-269 在前端原型落地：

- `/instances/:id` 直接渲染服务器统一控制台，不再只作为打开可组合画布的兜底入口。
- 服务器控制台已提供概览、控制台、文件配置、监控、玩家、插件、备份定时、业务、Bot 固定分区与顶部状态条。
- 列表点击服务器会同步到 `/instances/:id` 深链，面包屑与侧栏状态不再停留在列表路由。
- 玩家与备份定时按本轮规格第一版使用高密度预览或占位；超级工作台、导播台和可组合画布仍保留为高级拼屏入口。

## 替代方案

- **继续以画布为默认入口**：高级但不稳定，新手和深链体验弱。放弃。
- **恢复传统多 Tab 详情页并删除画布**：简单但丢失 FR-166/167/168 的差异化能力。放弃。
- **固定控制台与画布做两个完全独立实现**：会重复终端、文件、监控、业务组件。放弃，优先复用现有卡片内容。
