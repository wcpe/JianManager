# ADR-082：受控用户创建与邮箱邀请

- **日期**：2026-07-28
- **状态**：accepted（2026-07-28 用户审核通过；同日修订通过）
- **关联**：FR-001、FR-002、FR-156、FR-405

## 上下文

匿名 `/auth/register` 可创建 active 成员，且管理员创建用户错误地复用该路径。平台需要保留管理员直接创建，并让管理员通过邮件邀请外部成员自助设置凭据。

## 决策

1. 删除公开注册；初始管理员仅由现有一次性 `/setup` 创建。
2. 管理员直建用户使用平台管理员保护的单一 `POST /users`，不再使用注册后补角色的两步流程。
3. 邀请使用独立 `user_invitations` 表、32 字节随机令牌的 SHA-256 哈希、7 天时效、撤销和事务内原子消费。公开接受接口只能创建组成员。
4. SMTP 配置独立于告警通道，密码只允许环境变量引用；邀请邮件只能使用显式 HTTPS 公共基址，绝不从请求 Host 推断。
5. 不将邮箱写入 User，不新增找回密码、邮件队列或自动用户组绑定。

## 修订（2026-07-28）

替换决策 4：公共基址改为系统设置 `platform.public_base_url`，接受显式 `http://` 或 `https://` 地址，禁止查询参数和片段，且不得从请求 Host 或转发头推断。邀请首先使用该基址，后续所有需要生成绝对域名链接的能力复用此唯一真源。允许 HTTP 仅服务于无 TLS 的自托管内网部署；公开互联网部署仍应使用 HTTPS。SMTP 的独立设置仍位于系统设置中的邀请邮件分类，密码仍只允许环境变量引用。

## 后果

- 公开注册 API 是有意的破坏性移除；管理员 UI 改走新受保护接口。
- 邀请邮件投递失败不回滚邀请创建，管理员可在签发响应中取得一次性手动链接。
- 新表为加性迁移，旧用户、登录令牌和用户组不受影响。
