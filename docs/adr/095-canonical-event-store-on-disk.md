# ADR-095: canonical 事件体的落盘 compact 存储

- **日期**: 2026-09-24
- **状态**: accepted（**2026-10-30 部分推翻：存储介质已改为内存 tmpfs，见下方追记**）
- **关联**: FR-484 · FR-473 · ADR-094

> ### 2026-10-30 追记：事件段改 tmpfs，不再落磁盘
>
> **本 ADR 的标题与决策提案第 1 条（“追加式 NDJSON 段 + fsync 后原子替换 MANIFEST”）
> 已在存储介质上被推翻；决策的其余部分全部保留。**
>
> #### 前提怎么消失的
>
> 生产机的磁盘是**机械盘**（`/dev/sda7`，`ROTA=1`）。在这张盘上 fsync 是寻道 + 旋转惩罚，
> 而决策提案第 1 条恰把 fsync 当成达成崩溃一致性的必要手段。
> 用户 2026-10-30 裁定：「现在不做任何的索引 账本落盘 因为是机械盘 性能不行」。
>
> #### 新规则
>
> - `eventstore.MemoryRoot()` 把段根目录设为 `/dev/shm/jianmanager-events/<base>`
>   （无 `/dev/shm` 时回退 `os.TempDir()`）。写路径**不碰机械盘**。
> - 段格式、`MANIFEST.json` 语义、只增不减、按日分区、流式读回、`Store.DayMaxEnd`
>   等**全部保留**（决策提案第 3/4/5 条不变）。
> - 崩溃一致性简化为“重启即空”：不再需要“只容忍最后一段尾部截断”那套判据，
>   也不再需要目录项 fsync。
>
> #### 代价（必须如实读）
>
> **本 ADR 背景章写的那个承诺——“persistedSource.Events 是 VL 数据根丢失后重建 projection
> 的权威集合”——现在不成立了。** 段在 tmpfs 里，Worker 重启后它们就没了。因此：
>
> - VL 数据根丢失时，**无法再从事件段重建 projection**；重建只能依赖 VL 自身数据。
> - “事件体占用转移到磁盘”这条后果描述失效（现在是转移到内存盘）。
> - `eventStorePrune` 的段回收水位依赖 `VerifiedRuns`，而后者已从投递主路径移出，
>   该机制现在是“默认关闭 + 数据源已空”的僵态（生产未配置启用）。
>
> 这不是 bug，是刻意取舍：把“跨重启重建能力”换成“机械盘上无写入延迟”。
> 当前唯一跨重启存活的东西只有两样：**采集游标**（`ingest.cursor`，
> 每源一行几十字节，不 fsync）与 **VL 里的数据**。
>
> #### 代码落点
>
> - 介质：`internal/worker/logs/eventstore/store.go` 的 `MemoryRoot`
> - 装配：`internal/worker/logs/ingest/runtime.go` 的 `eventstore.Open(eventstore.MemoryRoot(...))`
> - 落地（提交见 git log）
>
> #### 不变的部分
> 段格式与 MANIFEST 语义、只增不减、幂等追加、内存上界能力、量测口径的两条硬约束、
> 以及「事件体落盘不能当作可按 reclaim 裁剪」这条区分（两者仍然严格分开）。

## 背景

FR-473 Shared Contracts §4.3/§5.3 规定 `persistedSource.Events` 是 VL 数据根丢失后重建 projection 的**权威集合**。该集合不可按 reclaim 前缀裁剪——裁剪（或在发布后清空事件体）会破坏归档导入、逻辑轮转与跨日分区重建的等价性，已被三个既有回归测试否决。

代价是它同时常驻内存并内联在 `ingest.state.json` 里，随单源留存事件数线性增长。真机 H-scale64 实测：64 源 × 3000 事件下 Worker 稳态 RSS ≈674MiB、`state.json` ≈143–189MB；量测归因显示主因**不是**事件体常驻（仅 +95MiB），而是 `persist()` 每轮对整份 state 做 `MarshalIndent` 的**瞬时分配**——单次即把 RSS 从 99MiB 推到 720MiB，且 Go 在 GC 后不把 `sys` 归还 OS。

按当时的容量拟合，1GiB 预算只够 ≈40 源，无法支撑「单 Worker 承载更多实例」。

## 决策提案

1. 新增 `internal/worker/logs/eventstore`：canonical 事件体按源存放为**追加式 NDJSON 段**，段清单 `MANIFEST.json` 在段内容 fsync 之后原子替换（`tmp` + `rename` + 目录 fsync），保持「先内容、后引用」。
2. `ingest` 的写路径（`writeProjection`）在投影发布成功后将事件体落段，**落段成功后才**在 state 上置 `EventsStored=true` 并清空内联切片；`persist()` 不再写回事件体，元数据用 `json.Encoder` 流式写入。
3. `ingest` 的读路径改走流式读：`canonicalRecoveryEvents` 从段读回完整集合（语义不变）、`deliver` 的身份去重集合从段重建、`publishedClosedForSource` 用 `Store.DayMaxEnd` 按日聚合。
4. 崩溃一致性：**只容忍最后一段的尾部截断**；中间段坏行、清单缺失/不可解析、清单版本不支持一律硬失败，不静默跳段（静默跳过会产生不可见的数据缺口）。
5. 旧格式迁移在启动时进行；**任一段写失败即整体放弃迁移**，保留旧格式继续运行（不丢数据、不半途改格式）。

## 理由

- 权威集合的**内容与语义完全不变**，只更换介质——这满足契约 §4.3/§5.3 的重建不变量，且不触碰已被测试固化的裁剪禁则。
- 事件体移出 state.json 后，`persist()` 的整份重写与瞬时分配同时消失，直接命中量测归因出的主因。
- 流式读让「重建」路径不再需要一次性 materialize 全量事件，使内存占用与源数量而非事件总量相关。
- 硬失败优先于静默修复：事件体是重建的唯一权威来源，任何静默跳段都会让「重建成功」这一结论失去依据。

## 后果

- `state.json` 体积与事件数解耦：64 源/192k 事件下由 **77 803 KiB 降至 139.5 KiB**，仅随源数量线性增长。
- 单 Worker 日志数据面密度大幅提升：**真机验收**（host-1 + 真 VictoriaLogs v1.52.0）实测
  64/128/150 源稳态 RSS 分别为 **22.5 / 22.3 / 20.0 MiB**、采集期峰值 **56.0 / 62.0 / 61.8 MiB**
  （目标稳态 ≤300MiB），对比改造前 64 源稳态 ≈674MiB、峰值 541MiB；
  独立正确性验证：342 个源逐一核对 **1 026 000 条事件零丢失零重复**。
  证据：`docs/specs/worker-log-canonical-eventstore/acceptance-real.md`。
- **补充决策（阶段5，2026-09-24）**：峰值与剩余常驻的根因经归因确认**不是**「单批归一化事件的分配」，
  而是三处**跨轮无界累积**结构——`Normalizer.events`、`NormalizeBoundary.linePos`、`Pipeline.delivered`，
  它们都随**会话内总行数**线性增长，与单轮读取量无关（故「限制单轮批量」的方案不对症，未采用）。
  现分别以 `Options.RetainEvents` 开关、`linePos` 滑动窗口 + `lineBase` 基准、`deliveredCount` 计数加界。
- 事件体占用转移到磁盘（150 源 × 3000 事件 ≈300MiB NDJSON，未压缩）。磁盘预算与保留策略仍由 FR-479/480 生命周期负责，本 ADR 不引入新压缩格式。
- **量测口径成为验收要求（两条硬约束）**：容量结论必须 (1) **全局保活被测对象**——把 `Manager`
  存入包级变量，`runtime.KeepAlive` 是编译期屏障、放在读数之后无效；(2) 取**稳态**（强制 GC 后）读数并对存活堆剖析归因。
  本 ADR 的早期版本曾因未保活而把稳态低估约 12 倍（发布过 25.9MiB，真实为 303.9MiB），
  也曾在脚手架内存污染下高估过一次（355MiB → 35.8MiB）。两次都靠剖析归因发现。

## 历史评审关注点

- 段格式的崩溃/截断恢复是否覆盖真实断电语义（目录项 fsync、部分行写入）。
- 迁移失败时的回退路径是否真的不丢数据。
- 幂等性：每轮 poll 传入的是完整权威集合，实现必须只追加差额。
- 「事件体落盘」是否被误当作「可以按 reclaim 裁剪」——两者必须严格区分。
- 长驻会话内的辅助结构（位置表、事件历史、投递记录）是否都有明确的释放时机；
  只写不读的累积是隐蔽的内存增长源。

## 取代关系

本 ADR 不取代 ADR-094（Worker 日志数据面边界）或 FR-473 契约；它细化 §4.3/§5.3 中权威集合的**存储介质**，不改变其内容、语义或裁剪禁则。
