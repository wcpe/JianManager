# ADR-055: 资源层级导航与页眉节点作用域

- **日期**: 2026-07-02
- **状态**: accepted
- **关联**: FR-267~272、FR-240、FR-241、FR-247、ADR-009、ADR-032、ADR-047

## 上下文

此前控制台主导航以“集群 / 观测 / 运营 / 系统”等功能域组织。该结构已比早期散乱一级菜单更清晰，但对游戏服务器运营者而言，最常见的问题不是“我要进入某个功能域”，而是“我要管理某个节点上的某台服务器”。

随着服务器数量向 1000+ 扩展，继续在侧栏内嵌实例树会让外壳膨胀，也会把单服能力打散到玩家、Bot、备份、插件等多个主导航入口。

## 决策

控制台导航主轴改为 **平台 → 节点 → 服务器**。

- 顶部页眉新增节点作用域选择器：`全部节点` / 单节点。
- 面包屑表达当前资源路径：平台、节点、服务器。
- 左侧导航只放跨服务器或平台级入口：平台首页、服务器、群组网络、观测、平台管理。
- 单服能力不再作为主导航散落，归入服务器控制台内部固定分区。
- 服务器选择不依赖常驻侧栏树，后续主要走全局搜索、全部服务器页、节点页与 1000+ 搜索分页能力。
- 节点作用域必须真实联动全部服务器列表、命令面板实例结果与创建实例默认节点；命令面板中的节点结果保持全局可搜，用于快速切换作用域。

## 理由

- **符合用户心智**：运营者先定位资源，再执行操作。
- **避免侧栏膨胀**：侧栏不承载 1000+ 实例树，保持稳定外壳。
- **保留跨资源视角**：观测、群组网络、平台管理仍作为跨服务器入口。
- **兼容后续规模化**：FR-247 的搜索 / 分页 / 聚合 API 可作为服务器选择器、全局搜索、列表页共同地基。

## 后果

- `ConsoleHeader` 承载节点作用域、面包屑、搜索、状态、任务、通知与账户；品牌固定在侧栏顶部，主题入口固定在侧栏底部。
- `ConsoleSidebar` 从功能域导航收敛为资源域 + 平台管理导航。
- `lib/breadcrumb.ts`、`lib/pageTitle.ts` 需要跟随新 IA 调整。
- 旧路由 URL 尽量保持不变，通过新侧栏归位，不破坏书签。

## 落地状态

截至 2026-07-05，本决策已随 FR-268 / FR-270 / FR-271 / FR-272 在前端原型落地：

- 页眉节点作用域已联动全部服务器列表、命令面板实例结果与创建实例默认节点；命令面板节点结果保持全局可搜。
- 侧栏已按平台首页、服务器、群组网络、观测、平台管理归位，主题入口固定在侧栏底部，移动端由底部导航与分组抽屉接管。
- 全部服务器、平台首页与日志中心等大数据页面使用 mock 1000+ / 一年窗口数据和虚拟渲染 benchmark 守护，不再依赖侧栏实例树承载规模化列表。
- 群组网络 `/networks` 与 `/networks/topology` 使用精确导航状态，避免两个入口同时高亮。

## 替代方案

- **继续五域功能导航**：实现成本低，但无法解决“单台服务器能力分散”和 1000+ 侧栏膨胀问题。放弃。
- **侧栏常驻实例树 + 顶部作用域**：双重实例选择会重复且拥挤，规模化后更难用。放弃。
- **只靠全局搜索，不保留资源导航**：对新手不可发现，也不利于节点 / 群组 / 观测类页面组织。放弃。
