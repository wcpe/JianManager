# ADR-087：沉浸控制台采用可见控制优先的工作台

- 状态：accepted
- 日期：2026-08-27
- 取代：第一版沉浸模式的 tmux 前缀键方案（未入库）
- 关联：FR-420（沉浸控制台壳）、FR-421（可视化分屏）、ADR-086（输出/输入分离）、ADR-067（会话保活）

## 背景

第一版沉浸模式把 tmux 的 `Ctrl+B` 前缀、window、键盘复制和底部状态条搬进 Web 页面。实际验收反馈明确指出：
这套交互不符合控制台页面的使用预期，功能发现性差，视觉上像被拉满的旧终端，且与浏览器已有输入、复制和导航心智模型冲突。

实例控制台本身已经有可靠的原生命令输入和鼠标锚点选择；沉浸模式应解决的是「收起页面外围界面、让日志和操作更专注」，不是复刻终端复用器。

## 决策

1. 沉浸模式保留 `F11` 进入/退出、`Esc` 退出或关闭当前浮层；**不注册 `Ctrl+B` 或任何 tmux 前缀状态机**。
2. 以顶部工作台头部取代底部 tmux 状态栏：显示当前实例、运行状态、TPS/在线/CPU、可见的退出与布局操作。
3. 多实例与分屏仍保留，但所有动作均可见且鼠标可达：添加控制台、左右/上下分屏、切换实例、聚焦、最大化和关闭 pane。上限为 4 个 pane，布局不持久化。
4. 键盘复制模式移除；复制继续复用 FR-418 的鼠标锚点选择、行复制和 HTTP 剪贴板兜底，避免第二套选区模型。
5. 每个 pane 是带标题栏的独立工作面；日志输出填满卡片，命令栏贴底，空输出有明确等待状态，避免无边界的大面积黑色空白。

## 后果

- 保留多 pane 的监看价值，但去除 tmux 学习成本与键位抢占。
- `ConsoleImmersiveMode` 的状态从第一版的 window / 前缀键 / 复制模式收敛为 pane 树、焦点、选择器和最大化状态。
- 第一版方案的 tmux 键位验收由视觉可发现性、鼠标操作和 F11/Esc 退出验收替代。
- `terminalSessionManager` 的会话保活、热集容量和输出/输入分离均不变。

## 修订（2026-09-07）：工作台家族融合与「专注终端」命名

超级工作台（FR-167，跨实例自由网格画布，9 种卡混排）与本沉浸台都覆盖「多实例终端并排 + 全屏」，
双入口造成认知冲突。经评审选定**统一入口、职责分层**（不合并代码）：

1. **命名统一**：本能力对外称「专注终端」（`consoleImmersiveEnter/Exit/Label` 三键同步）；
   「沉浸工作台」保留为内部与文档称谓。
2. **超级工作台新增「专注终端」入口**：工具条按钮以画布上首个终端卡实例为起点进入沉浸台；
   画布无终端卡时按钮常驻禁用并提示先拖入。退出回到来路（工作台页或实例页）。
3. **职责分层**：监看混排（多卡同屏、预设、轮播）归超级工作台；纯终端重度操作（树形等分、
   F11 专注、命令栏输入）归专注终端。两表面共享 `terminalSessionManager` 会话，切换不断连、
   不丢缓冲（会话释放边界见 console-immersive-workspace spec §3.1）。

后果：入口互通、认知统一，消除「多开终端该去哪」的分歧；两套布局模型（树形等分 vs 自由网格）
各自保留、不做代码级合并；从工作台进入时仅提供起点实例，用户在沉浸台内仍可自由切换与分屏。
