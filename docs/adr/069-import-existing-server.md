# ADR-069: 导入现有服务器（就地接管 / 搬迁托管区）

> 编号占位：XXXX 由主控整合时统一分配真号，本文件名与标题届时一并改写。

- **日期**: 2026-07-12
- **状态**: accepted（修订 ADR-007：其「用户自填工作目录——保留为『导入已有目录』高级模式」的预留正式落地为导入向导，ADR-007 其余决策不变）
- **上下文**: 运营商上面板前往往已有跑着/存量的服务器目录，现只能新建实例再手工搬文件。FR-302 落地 ADR-007 当年预留的高级模式：面板向导选中节点上的现成目录 → Worker 探测（核心 jar / 内嵌 JDK / `server.properties` 端口 / eula）→ 一键收编为受管实例。需要决策三件事：导入实例的工作目录例外、删除语义、搬迁策略。
- **决策**:
  1. **工作目录例外（就地接管）**：导入模式二选一。`in_place` 就地接管时实例工作目录 = 原目录的**绝对路径**，是「工作目录一律系统分配、落托管区 `var/servers`」（ADR-007/ADR-010）的**唯一合法例外**；实例加列 `work_dir_in_place`（bool，默认 false）显式标记，UI 以「就地导入」徽章呈现。该例外仅由导入流程内部产生：CP `CreateInstanceRequest` 经**包内未导出字段**预置工作目录，外部 API 依旧无法手填任意路径，路径穿越面不扩大。
  2. **删除不碰就地目录（双保险守则）**：就地实例删除时——① CP 在 `RemoveInstance` RPC 显式传 `skip_work_dir=true`，Worker 直接跳过目录删除；② 即便标记丢失，Worker 既有托管区守卫（`remove_instance_ops.go`：目录不在 `var/servers` 内一律拒绝 `RemoveAll`）天然兜底。两道保险独立成立，任一生效即原目录完好；删除确认文案必须明示「不会删除原目录」。
  3. **搬迁策略（migrate）**：`ImportServerDir` 把原目录整体搬入托管区系统分配路径 `var/servers/<slug>-<shortid>`（slug 由 CP 按实例名生成，Worker 校验 slug 合法性防越界）。**同盘优先 `os.Rename`**（O(1) 原子）；rename 失败（跨盘/跨设备）回退**递归拷贝 + 文件数与字节数双校验 + 校验通过后清源**；校验不一致即删除半成品目标、保留源目录原样报错。拷贝回退路径不支持符号链接等特殊文件（遇到即中止报错，源目录不动）。V1 同步执行，大目录建议就地接管（向导提示）。
  4. **探测只读且带守卫**：`InspectServerDir` 只读探测，jar 候选深度 ≤2 且已知核心名（`server.jar`/`paper-*`/…）排前、MANIFEST `Main-Class` 仅作排序提示；`jre*`/`jdk*`/`runtime`/`java` 子目录经 JDK 探测（`jdk.detectAt` 语义）可勾选登记进 `node_jdks`（`managed=false` 外部登记语义，平台永不删其文件）。守卫：路径必须绝对、存在、为目录，且**不得指向托管区之内**（防重复收编已受管实例）或托管区的祖先目录（防搬迁自吞）。
- **理由**:
  - 就地例外以显式列 + 内部专用通道收口，既满足「接管不动目录」的真实需求，又不推翻 ADR-007 系统分配原则（默认路径不变、外部 API 不开口子）。
  - 删除双保险：单靠 CP 标记怕状态漂移，单靠 Worker 守卫怕托管区语义变化；两道互相独立，用端到端测试锁死。
  - 同盘 rename 是零拷贝原子操作；跨盘拷贝必须先校验再清源，宁可失败保源目录也不产出半截搬迁。
- **后果**:
  - `instances` 表加列 `work_dir_in_place`；proto `WorkerService` 追加 `InspectServerDir` / `ImportServerDir`，`RemoveInstanceRequest` 追加 `skip_work_dir`。
  - 就地实例的备份/克隆等按既有绝对路径 grandfather 语义工作；其目录生命周期归用户，平台只读写内容不负责删除。
  - 审计新增 `instance.import.inspect` / `instance.import` 两个 action（中英翻译随 FR-302 进 `audit.actions.*` 键）。
- **替代方案**:
  - 只支持搬迁、不支持就地 —— 无法覆盖「目录被其它工具/脚本引用不可动」的存量场景，否决。
  - 就地实例删除时连原目录一起删 —— 平台无权处置用户自管目录，误删不可逆，否决。
  - 跨盘搬迁交给用户手工 —— 与「一键收编」目标相悖，否决（大目录耗时风险以向导提示 + V1 同步执行承担）。
