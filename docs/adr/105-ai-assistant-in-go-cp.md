# ADR-105: AI 助手内置在 Go Control Plane

- **日期**: 2026-10-22
- **状态**: accepted（FR-514 已按本决策实现，尚待真机供应商验证）
- **关联**: FR-514～520 · 不取代 ADR-076/080/096，不改动 `/api/v1/mcp` 契约

## 上下文

产品需要把「聊天问问题 + 按当前页上下文排查」放进运维面板：登录后默认进入带提问区的首页，其他页面能呼出同一个助手，并能接入系统自身的运维工具与管理员配置的外部 MCP 服务。

现状事实：

- Control Plane 是唯一浏览器入口，前端经 `go:embed` 内嵌，单二进制部署是既定形态（ADR-005）；后端语言为 Go（ADR-001），不为前端或辅助能力单独引入 Node.js/Python 常驻服务。
- 已存在**面向 Agent 的** MCP 网关（ADR-077/096），但它只接受 `jmat_` Agent Token；人类 JWT 不是 MCP 凭据。其工具面按 Token 能力裁剪，且平台治理与秘密面为永久禁区（ADR-076/080）。
- 没有任何模型供应商适配、对话运行时、会话存储或外部 MCP 客户端。仓库也无官方 Agent 运行时依赖。
- 用户已确认：所有登录用户可用，但只能用自身原有权限与资源；读取自动、写入必须由用户确认；外部 MCP 首版只要远程 Streamable HTTP。

核心矛盾是：**需要一个能理解自然语言、自由组合多步工具调用的执行体，而现有 MCP 工具面是为「持有平台级或显式 scope 的自动化凭证」设计的**。直接把人类 JWT 接进 `/api/v1/mcp`，等于让任意登录用户凭借自身 RBAC 反复触发一批原本只由窄 scope Token 触发的写工具，并让「模型说什么就做什么」变成新的提权面；复用管理员 Agent Token 则更糟——会把平台范围隐式授予所有用户。

## 决策

1. **助手运行在 Control Plane 进程内，纯 Go 实现**。不新增 Node.js/容器侧车常驻进程，不把模型调用或工具循环放到浏览器（密钥离浏览器，策略在服务端）。外部 MCP 由 CP 作为客户端出站，不监听入站端口。

2. **人类用户身份与 jmat Agent Token 是两条独立授权链**。新增受限用户委托执行器：复用 action 描述、真实目标解析与领域 service，但每次执行都重新装载当前 `UserAccess` 并校验账号状态、授权版本、动作权限与资源归属；不构造假 AgentPrincipal，不引入「会话内权限快照」。现有 `/api/v1/mcp` 保持只认 Agent Token。

3. **工具暴露不等于授权**。发现阶段按当前用户可见范围裁剪只是减噪；每次真正执行都要重新解析目标并过原领域门禁。只读与写入分开登记；实例读权不推导为整机管理权。

4. **所有写入必须逐调用确认，且确认不提权**。确认对象绑定用户、会话、run、调用、工具/schema/策略版本、规范化参数哈希、真实目标指纹与期限；服务端重验后 CAS 消费。不可命中的、过期的、参数或目标变化的确认一律不执行。模型与 Agent 永远不能自行批准。

5. **对话与执行状态持久化在 CP 业务库**：会话按用户隔离，run 有显式状态机与唯一活跃槽，事件只追加并可续读。进程重启把未完成 run 标为中断；工具写入结果不明的标待核实，不自动重放。

6. **外部 MCP 首版仅远程 Streamable HTTP**，管理员配置、凭据留 CP；共享的管理员级上游凭据不自动授予普通用户。不引入 stdio 子进程、旧双端点 SSE 或通用 OAuth 托管。供应商与外部连接的出站都走受保护 factory：默认禁私网、显式放行、每次解析与拨号校验并固定目标、拒绝元数据地址、代理不当作防护。

7. **默认首页改为 AI Dashboard，经典首页以显式 URL 模式保留**。两者按需挂载，经典模式不因模型不可用而失效；助手入口跨路由常驻但共用单一会话状态，不随路由卸载或重复生成。

## 理由

- **纯 Go 保住单二进制与三进程模型**：引入一个 Node 常驻服务或子进程会新增生命周期、文件权限与依赖管理面，且与本项目「Bot Worker 才由 Worker spawn」的边界冲突。模型适配只用标准库 HTTP/SSE，成本可控。
- **不复用 jmat 通道是为了不扩权**：Agent Token 的 scope 表达能力弱于人类 RBAC 树与组归属；把用户映射成一个宽 scope Token 会失去组隔离。反之把 JWT 塞进 MCP 网关，会让一批按「自动化凭证」设计的工具落入交互式模型操作，风险面等于模型替用户连点按钮。
- **逐调用确认**是对「模型基于不可信文本自主行动」的必要约束：它与既有危险操作二次确认（ADR-029/104）方向一致，但不把领域 DANGER 门禁挪到聊天层，领域仍作最终防线。
- **不借用现有审批票据内核的实现状态**：平台级审批（FR-490～493）仍为计划。助手切片先冻结一张可复用的票据/回执抽象并标明来源与策略，未来平台审批可接入；不能因为「迟早要统一」而先交付一个无确认的写通道。
- **持久化 run/event 而非纯内存**：聊天是可中断的长交互，页面刷新与断流常见；只靠进程内状态会让工具调用与确认失去可解释性。
- **外部 MCP 只走 HTTP**：stdio 需要本机进程与宿主信任，是桌面单用户应用的假设，与服务端多用户面板不符；旧式 SSE 双端点可被请求范围 SSE 覆盖。

## 后果

- 新增 `model/`（供应商、模型、会话、run、事件、确认）、`service/`（模型适配、运行循环、用户委托、连接治理）与 `router/` 的 `/api/v1/assistant/*`；经既有鉴权链挂载。
- 新增凭据存储但**不新增第二套主密钥**：复用既有装配得到的 KeyEncryptor；`null` 加密器必须显式拒绝写入而非写出空串。主密钥丢失/更换显式不可用，不明文回退。
- 新增受保护出站客户端（供应商 + 外部 MCP 共用），默认拒绝内网与元数据地址，并覆盖代理/CONNECT/SOCKS 的目标固定问题。
- 迁移新增表；须过「迁移→首启→停→二启→三启」与脏库验证。当前可执行驱动只有 SQLite，ADR 不承诺 MySQL。
- 前端新增默认首页模式、共享聊天面板与 `/settings/ai` 配置页；经典首页与既有仪表盘数据口径不变。
- 测试面：用户隔离、越权/组外、确认幂等与过期、断流续读、重启中断、凭据脱敏、SSRF/重定向、外部工具失败隔离，以及真实供应商/真实远程 MCP 的端到端闭环（凭据由环境注入，缺失则如实标注未验）。
- 不引入多代理、通用 Shell、CP 任意文件访问、工程工作区、Hooks、代码回滚、RAG/向量库、附件多模态或计费系统。

## 被否的备选

- **复用 `/api/v1/mcp` 并放宽为 JWT**：破坏 ADR-076/080 的能力模型，且让 scope 语义与 RBAC 树分叉，审计无法区分人机。
- **为每个用户签发内部 jmat Token**：Token 的生命周期、吊销与 scope 收敛都无法跟上请求级 RBAC 变化，还会让 secret 数量随用户增长。
- **前端直连模型供应商**：密钥落浏览器、策略无法服务端强制，且无法做用户级限流与审计。
- **新增 Node 侧车运行某一现成 Agent SDK**：与单二进制、三进程模型冲突，收益仅是少写一层适配。
- **外部 MCP 支持 stdio**：需在服务器上执行管理员输入的命令，等价于本机任意代码执行面。
