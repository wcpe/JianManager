# ADR-109：实例日志高级查询使用受限过滤表达式与独立授权选择器

- 状态：已采纳；自动化回归先行，真实 VL 与浏览器联合验收另行记录
- 日期：2026-11-12
- 关联：FR-558；[高级查询规格](../specs/logs-advanced-query/spec.md)、[ADR-094](094-worker-log-local-data-plane.md)、[ADR-102](102-log-partition-catalog-from-victorialogs.md)

## 背景

实例日志查询已经具备 Query View、授权目标、时间窗、复合游标、聚合和导出闸门；普通 `keyword` 实际承载 LogsQL 过滤表达式。页面新增高级输入时，如果另起一条不受约束的原始查询通道，或者只在新参数上检查语法而保留旧入口旁路，就会出现作用域、结果类型、缓存和导出身份不一致。

Worker 的查询适配器已将物理授权 selector 写入 VL 的 `query`，将用户过滤写入 `extra_filters`；两者由 VL 分别解析并取交集。这个边界必须保留。括号校验或字符串拼接不构成授权机制，不能代替它。

## 决策

1. 高级模式使用现有日志端点，显式传 `advanced=true&logsQL=<filter>`；普通模式继续使用 `keyword`。两个输入互斥，不能同时提交非空条件。平台和节点文本日志不开放高级模式；默认实例工作台和非平台用户仍可使用其授权实例内的高级过滤。
2. 高级输入是 **LogsQL 过滤表达式**：保留字段条件、布尔组合、匹配/正则及时间过滤；不开放 `stats`、`union`、`stream_context` 等管道。统计使用既有 Stats/Facets 接口和分析区域，以保留事件列表、分页、字段与导出的固定结果模型。
3. `keyword` 与 `logsQL` 使用相同词法边界：最多 8192 UTF-8 字节，检查字符串、分组与区间边界，拒绝未加引号的管道、注释、非法控制字符和超过 64 层的嵌套；支持单引号、双引号与反引号。引号内的 `|` 是合法文本/正则，不按管道拒绝。具体字段/函数是否合法仍由 VL 解析，不自行实现第二套查询语言。
4. 授权仍由 CP 的真实用户权限和目标集合计算，绑定 Principal/PermissionScope 和 Query View。用户表达式仅进入 VL `extra_filters`；CP/Worker 独立强制目标 selector、`[from,to)` 时间窗、封窗与预算。表达式中的 `OR`、`log_source_id` 或 `_time` 只能缩小授权交集，不能扩张授权目标或时间范围。
5. 高级查询设置整请求上限：32 MiB 扫描字节、30 秒、64 路 Worker、普通页面最多 1000 条结果。请求可用 `maxBytes`、`timeoutMs`、`maxFanout` 收紧，不能扩大；非法/零/负值报错。整窗导出的行数仍由既有导出配置共同限制，不把普通页面行上限误用为全量导出范围。分页读取可以为安全游标多读一条前瞻事件。
6. Search、门面和兼容 Tail 响应增加可选 `query_meta`，提供实际预算、返回行数与处理耗时。它不提供无法证明的存储扫描总量，也不把预算上限冒充实际扫描字节。高级前端遇到没有该确认字段的旧 CP 时拒绝呈现所谓高级结果，避免旧 CP 忽略参数后返回未筛选日志。
7. 前端区分输入草稿与已应用表达式。高级模式按 Enter/查询应用，普通模式保持原来的去抖查询；未应用草稿、请求中、失败或旧占位结果均禁止导出。模式/表达式进入 scope identity，聚合、分页、缓存和导出复用同一已应用 scope， inactive 输入不参与请求。切回普通模式保留普通输入。
8. 复用 AbortSignal、HTTP context、Worker deadline 和已有 429 退避；提供显式取消，显示可行动的服务端错误。未知/不支持/失败保持非成功空态，不能以“0 条”伪装成功。高级查询的访问记录包含主体、scope、时间窗、预算、HTTP 结果、取消和耗时；查询输入仅记内容摘要和字节数，避免把凭据或个人数据写入日志。

## 替代方案

| 方案 | 结论 |
|---|---|
| 将任意 LogsQL 管道直接透传到事件列表接口 | 结果形态可以变成聚合表或跨流上下文，与固定事件游标、覆盖和导出契约冲突；本次不采用 |
| 仅给新 `logsQL` 参数加校验，普通 `keyword` 不变 | 留下语法旁路，两套输入对同一数据面不一致；不采用 |
| 将所有 `keyword` 转义为纯文本 | 会破坏已有字段/流过滤和合法布尔表达式；不采用 |
| 将用户表达式与 scope 拼成一条字符串 | 布尔优先级和管道可能与安全 selector 交互；继续使用 VL 独立 `extra_filters` |

## 后果与验收边界

- 能复用已有只读查询、权限、聚合、分页、取消和导出链路，没有新增数据库表或 Worker RPC。
- 非法的旧 `keyword` 管道/括号输入现在会在 HTTP 层明确拒绝；合法字段和正则过滤不改变。
- 对普通文本日志、任意 VL 数据管理和浏览器流式订阅均不新增能力；流式订阅由后续规格定义。
- 自动化需覆盖两个表达式入口、授权/时间独立性、预算钳制、取消传播、跨模式导出、旧 CP 拒绝、错误和原生输入行为；真实 VL 解析及浏览器交互必须另做联合验收，不把 mock 通过写成真机通过。
