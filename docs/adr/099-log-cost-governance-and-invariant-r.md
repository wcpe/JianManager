# ADR-099: 日志成本治理与不变量 R（采样折叠 / 默认不丢 / 单位成本结论）

- **日期**: 2026-10-02
- **状态**: accepted
- **关联**: FR-498（单机 60 实例压测与容量基线、采集侧成本攻坚）· [ADR-094](094-worker-log-local-data-plane.md) · [ADR-095](095-canonical-event-store-on-disk.md) · [ADR-098](098-log-retention-tiering-and-archive.md)（保留与分层）· `docs/specs/log-cost-governance/spec.md` · `docs/specs/log-verify-chunking/spec.md` · `docs/specs/log-index-sqlite/spec.md` · `docs/specs/worker-log-platform-contract/spec.md` §4.3/§9

## 上下文

日志平台在功能上已经完整，但**成本结构不可持续**，且两次生产事故证明它对自身风险毫无观测：

1. **单位成本 8.3×**：实验室 0.36 ms/行 → 生产 2.95 ms/行（61 台实战压测：达成率 0.791，打点 p95 48–52 ms，CPU/内存/IO 全闲，瓶颈全在流水线自身）。
2. **成本随运行时长线性增长**：投递路径每批做 3 次 O(段总行数) 全量遍历——身份集合重建、权威全量（`canonicalRecoveryEvents`）、段行数校准（`eventstore.Iterate` 实测 8.4–9.0 µs/行，段只增不减）。这是"越跑越慢"的机制性根因。
3. **无成本治理手段**：没有采集侧过滤/采样、没有降级档位、没有每源预算；唯一的降级是磁盘维度（80% DEGRADED / 90% PAUSED）。
4. **两次事故的形态**：2026-09-28 状态文件涨至 1.2 GB、117 MB/s 持续重写 25 小时；2026-10-01/02 缺口风暴把 10 个源焊死在暂停态、**13+ 小时零新数据**。第二次的根因链是"投递失败 → 记缺口 → 缺口挡住恢复 → 不再产生新批次 → 缺口永无出口"。
5. **诱惑与风险**：面对成本压力，最直接的诱惑是"低价值级别直接丢"。但缺口自动消解的判据是「缺口必须完全落在**某一段**连续覆盖区间内」（复审 P1-1 明确否掉了凸包判定），而连续区间是从**实际投递的事件**的 `Record` 区间折出的。**任何让事件凭空消失的抑制都会造出空洞，使该源被永久焊死**——这正是事故形态。因此成本治理必须先有一个可证明的安全性不变量。

## 决策

### 1. 不变量 R（区间守恒）是本项的一等不变量

**陈述**：对任何一个日志源，把本批次被消费的行按位置升序排列，其 `Record` 区间必须是一条连续覆盖；**采集侧的每一次"抑制"都不得在这条覆盖上留下空洞**。

**形式化**：`MergePositionRanges(Process(in)) == MergePositionRanges(in)`（逐段相等）。

**实现方式**：抑制不丢弃，而是把被抑制的行替换为**汇总事件**：

- `Record` 区间 = 被抑制行的**精确并集跨度**（只在区间相邻时合并，**绝不是 min..max 凸包**，绝不跨越未被抑制的事件）；
- 段内必须**同级别、同流、同规则、同源**（汇总的 `level`/`stream` 字段不撒谎）；
- 汇总事件**走完整管线**（WAL → 投递 → 逐字段校验 → 发布），与普通事件无差别；
- 汇总事件的 `EventID`/`CanonicalHash` 用**与普通事件同一套契约推导**（不得使用 `agg-<start>-<end>` 之类人造 ID，否则投影校验按 `event_id` 查表时会查不到自己）；
- **确定性**：抑制决策只依赖事件自身携带的数据（级别/流/正文/`EventTimeUTC`），**不读挂钟**——重放必然得到同一汇总事件，账本 `(EventID, CanonicalHash)` 去重语义不受影响。

**回归锚点**：`R1`（随机多轮逐段相等）、`R1b`（乱序时间戳）、`R2`（**缺口跨越被抑制区间仍能自动消解**，真实账本 + 真实判据 + 真实允许名单）、`R2b`（**反证**：朴素丢弃下同一缺口消解不掉，精确复现 13 小时零数据形态）、`R3`（输入自带空洞必须原样保留）、`R4`（汇总就是普通事件）。

### 2. 丢弃型采样默认关（D2①）

- `log_ingest.sampling.enabled` 默认 `false` ⇒ `Process` 恒等返回入参，逐指令等价于改动前；
- **所有抑制都是"折叠为汇总事件"**（区间可查、正文写明被抑制条数与首条样例），不是静默丢弃；
- **不可恢复的丢弃需要显式开启**：平台不做"默认把 info/debug 丢掉"的决定；
- 契约 §4.3「未确认数据不被静默删除」与 §9 的验收条款不因成本治理放宽。

### 3. 采集侧策略集：可配置、默认关、粒度按规则而定

| 策略 | 语义 | 默认 |
|---|---|---|
| 等级过滤 | 低于 `min_level` 的折叠为汇总；**无法归类的级别一律放行** | 关 |
| 同源同消息高频抑制 | 窗口内同签名折叠为一条 + 计数 | 关（阈值为 0） |
| 每源预算 | 窗口内超出预算按比例保留（quota → 采样比） | 关（预算 0） |
| 风暴自动降级 | 由外部读数（磁盘）驱动，**只抬高 `min_level`**，不改变其他语义 | 关 |

**归并粒度不是可选的细节**：等级过滤 / 风暴降级按 `(级别, 流)` 归并；高频抑制 / 预算按 `(级别, 流, 模式)` 归并。若等级过滤也按模式归并，一百条互不相同的 DEBUG 会产出一百条各自只有一条的汇总——体积没省下来，还多一层包装。

**配置校验读原始取值而不是 `Normalize()` 之后的值**：后者会把"阈值填 -1"悄悄当成"没填"，使校验成为死代码（该缺陷由变异实验 M10 发现）。

### 4. 单位成本：投递路径的 O(段总行数) 遍历必须消除（提交 `87af507f`）

- **根因**（大段夹具 + 生产窗口 + 真 VL 探针联合定位）：`deliver` 每批三次段全量遍历——`seen` 身份集合重建、`canonicalRecoveryEvents` 权威全量、`appendEvents` 的 `Count` 校准；段只增不减 ⇒ 成本随运行时长线性增长。
- **改法**：**尾段快路径**，三条安全判据同时为真才走（非 replay / 非 `PublicationPending`；权威集合不在内联切片；本批最小 `record_start` 同时 ≥ 段水位与投递水位）；快路径只遍历本批 + 段增量追加 + 行数/发布水位缓存；**重叠或回退区间必回退全量**，偶发冲突由 verify fail-loud 兜底。
- **实测（同规格夹具）**：批耗时 8307 → 1490 ms（**−82%**）、吞吐 1693 → 2841 行/s（**+68%**）、达成率 0.555 → **0.93**（峰值 1.01）、快路径命中 354/354。
- **门禁**：变异 A（禁用快路径）/ B（去掉双水位判据）实测转红后逐字还原；`-race` 全绿。

### 5. 新鲜度-成本曲线：不做"以新鲜度换成本"的批拉改造

实测结论（`87af507f` 一并产出）：**积压场景的批已封顶 2000 行**，把"tail 到即发"改成 flush 窗口/分段批拉**收益为零**，只会加长可见延迟。故该项**不实施**，仅作为观测结论保留（如未来批上限或投递语义变化，需重测后再评估）。

### 6. 运行期日志等级可调

`log.level`/`log.format` 此前**没有任何装配点**（Worker 从不调 `slog.SetDefault`，两键形同不存在）；现装配并暴露 `LevelVar` 作为运行期动态调等级的接线点，非法值启动即拒。现场排障可临时开 debug、平时压到 info 以降开销。

### 7. 多租户配额（D4）：先可见性，后强制

- 现有 `GroupQuota` 只有 `MaxInstances/MaxBots/MaxStorageMB` 与 `EnforceMode(alert|throttle|stop)`，**没有日志量维度**；
- 路线：**先做用量可见性**（每源/每组的写入量、磁盘增量、投递/校验耗时读数），**强制档位后置**——在度量口径稳定前做强制，会把"配额不准"变成"运营事故"；
- 采集侧"每源预算"（第 3 条）是**机制**，平台侧多租户配额是**治理**，两者不互相替代。

### 8. 可观测性关联（D5）：轻量 correlation id，不引入 OTel 全家桶

- 平台自身操作（下发命令、触发迁移、发起查询等）产生 correlation id，贯通 CP → Worker → 采集事件字段 → 查询/导出；
- **不引入 OpenTelemetry collector/SDK、不做全量 trace**（管理面不是业务请求链路，全量 trace 会把量级再抬一档）；
- correlation 字段**不得进入 `stream_fields`**（契约 §3.1 禁止高基数字段进入流身份），只能作为结构化字段参与筛选。

### 9. 硬规则：降级与采样不得绕过既有不变量

任何采样/降级/预算都不得削弱：缺口自动消解的 **default-deny 允许名单判据**、`VerifiedRuns` 区间凭据、至少一次投递与重复对账、verify 的 fail-loud 语义、`closed_visible_seq` 的封闭前缀语义。上述判据的既有回归必须保持全绿——它们是"省成本"与"不丢数据"之间的边界。

## 理由

- **为什么必须把不变量 R 写成一等不变量**：它不是一个"整洁性要求"，而是**事故形态的免疫**。缺口判据建立在"投递事件的区间"之上，抑制造洞 ⇒ 缺口永不可消解 ⇒ 源被永久焊死。把这条写进 ADR，是为了让后来者在"想加个过滤"时先看见这条边界。
- **为什么默认不丢**：本产品的日志是排障素材，且当前的性能瓶颈（verify/O(N) 遍历）已由可逆手段解决（本 ADR 第 4 条 + 校验侧分簇并发）。在可逆手段尚未穷尽前引入不可逆丢弃，收益有限而风险不可逆。
- **为什么先测后修**：`87af507f` 的收益来自先定位（大段夹具 + 生产窗口 + 真 VL 探针三方交叉），而不是猜。把"每批 3 次全量遍历"这一机制写进 ADR，避免后来者再把它当作"反正要遍历"而复现。
- **为什么放弃分段批拉**：有实测结论支持的"不做"与"做"同样重要——它能阻止后续重复投入。

## 后果

- **正面**：单位成本的主要机制性来源被消除并留有可转红回归；成本治理手段齐备但**默认全关**，启用与否是运维的显式决定；采样在结构上不可能破坏缺口消解（不变量 R）。
- **代价与边界**：
  - `log_ingest.sampling.*` 的策略语义与 `log_retention.*` 的档位必须与 `docs/specs/log-cost-governance/spec.md` 同步演进；变异 11/11（sampling）+ 32/32（retention，含驱动器 5 条）以断言转红为门禁。
  - **未决策项**：**分级验证**（低价值级别"只存不验"）尚未决策与实现——它削弱的是"逐字段校验"的证据链，收益与风险需单独评估后再定，**本 ADR 不承诺**。
  - **未实现项**：指标端点尚未接线（`sampling.Stats`/`ArchiveStats`/`SweepStats`/`DriverResult` 已有读数，仅日志行可见）；`JIANMANAGER_STAGE_TIMING` 阶段观测已具备，但成本可见性（每源 GB/天、ms/行）仍未平台化。
  - **FR-485 其余观测项**（state 文件尺寸与增速、persist 写字节/秒、单源 WAL 积压与暂停时长、投递失败率与分类、校验退避次数、慢 SQL、节点 iowait、比率触发）仍属未实现，是两次生产事故"靠人肉发现"的直接原因，优先级不因本 ADR 降级。
- **可转红防护**：`sampling` 11 条变异 + `retention` 32 条变异全部以断言转红；`TestInvariantR2`/`TestInvariantR2b` 是本 ADR 的核心安全锚点——移除它们等于放弃"抑制不造洞"的证明。
- **不影响**：`.claude/rules/architecture-invariants.md` 与 `decision-alignment.md` 的同步不在本次写入范围（由文档纪律流程后续处理）。
