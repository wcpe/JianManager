# ADR-086：控制台输出/输入分离，输出区弃 xterm 改 DOM 虚拟列表

- 状态：accepted
- 日期：2026-08-27
- 关联：FR-415（输出/输入分离）、FR-416~419（在此地基上的能力）、ADR-067（终端会话保活）、ADR-081（终端经 CP 中转）
- 取代：不取代既有 ADR，但**推翻 `Terminal.tsx` 中"用 xterm 承载输入"的实现决策**（该决策未曾立 ADR）

## 背景

实例控制台自始用 `@xterm/xterm` 同时承担两件事：渲染服务端输出，以及接收用户输入。

但 Worker 侧给的**不是 pty，是 stdin 管道**：`internal/worker` 只把游戏服进程的 stdout/stderr 原样按行转发，
反向也只是把用户输入写进 stdin。没有终端设备、没有行规程（line discipline）、没有窗口尺寸语义（`resize` 消息
对 MC 服务端进程无实际作用）。

于是 `Terminal.tsx` 不得不在 `onData` 里**手工重建一套行编辑器**：逐字符回显、手工处理退格、
手工实现 ↑↓ 历史。结果是它长着终端的样子，却没有终端的能力：

- 光标不能左右移动（按 ← 只会往 stdin 发 `\x1b[D`，服务端不认）
- `Ctrl+A/E/W/U` 等 readline 惯用键全部失效
- 中文输入法的组合输入过程会被逐字符回显打乱
- 粘贴要走被自定义右键菜单劫持的路径（且 `readText()` 在 HTTP 下不可用，见 FIX-1）

同时，xterm 是 canvas 渲染，**屏幕上没有 DOM 行节点**。这直接堵死了运维排障真正需要的能力：
按级别过滤、行级悬停复制、Java 异常堆栈折叠、行级高亮、跨大范围的可靠选取。

## 决策

**把输出与输入拆成两个组件，各用适配其职责的技术。**

### 输出区：DOM 虚拟列表

- 结构化行模型 `LogLine { seq, ts?, level?, source?, body, kind }`，由**日志行解析器**从原始文本产出
- 虚拟列表只渲染可视窗口 + overscan；行高固定以简化定位
- 环形缓冲上限 **5000 行**，超出丢弃最旧（更早的历史由 FR-419 从数据库游标分页取回）
- ANSI 转义自行解析为 span（MC/Paper 实际只用 SGR 16 色 + 粗体，不需要完整终端仿真）
- 只读：不接受键盘输入，`user-select` 允许，但跨行选取由 FR-418 的锚点选区接管

### 输入区：原生 `<input>` 命令栏

- 用浏览器原生输入控件，**行编辑、输入法、粘贴、撤销全部免费获得**，不再手工模拟
- 提交时整行发往 stdin（`{type:'stdin', data: line}`，**不补行尾**——Worker 侧三种启动策略各自补），不逐字符发
- 历史、补全、多行粘贴保护属应用层能力（FR-416），与行编辑正交

## 为什么不是其他选项

| 选项 | 否决理由 |
|---|---|
| 保留 xterm，只把输入换成 `<input>` | 能修好输入手感，但输出侧的过滤/折叠/行级操作**在 canvas 上做不到**。而这些正是排障主诉求（用户原话：Java 堆栈难复制、大范围拖选、往上翻历史） |
| 保留 xterm，输出能力靠 addon 补 | 无 addon 能提供"隐藏部分行"或"给某行挂按钮"——这需要 DOM |
| 让 Worker 侧提供真 pty | 违反架构不变量的进程模型（游戏服由 daemon wrapper 托管，见 ADR-003），且 MC 服务端本身不是交互式 TUI，pty 的能力用不上却引入终端仿真的全部复杂度 |
| 后端把日志结构化后再下发 | 值得做但不在本批：会改 Worker→CP→浏览器的消息契约与 `logs` 表模型，影响面远大于前端解析。前端解析可先落地，后端结构化是独立议题 |

## 代价（明确接受）

1. **自行实现 ANSI 解析**（约 200 行）。风险可控：MC/Paper 输出的转义序列种类极少，
   解析器对不认识的序列一律**原样丢弃而非渲染成乱码**。
2. **虚拟列表的选区断裂**：只渲染可视行 → 原生跨行选区拖出屏幕即断。这是 FR-418 存在的原因
   （锚点选区取自数据源而非 DOM），不是可以忽略的小瑕疵。**单行内仍用原生字符级选区**。
3. **失去 xterm 的成熟度**：滚动性能、宽字符处理、搜索 addon 都要自己保证。
   性能上以"灌 10000 行仍 ≥50fps"作为验收闸。
4. **`@xterm/*` 依赖不能立即移除**：遗留 `components/Terminal.tsx` 与兼容测试仍需这套渲染器；
   依赖清理是后续 refactor，本 ADR 不把它混入输出/输入分离改造。
5. **不再兼容"服务端驱动光标"的输出**（如进度条原地刷新 `\r`）。
   MC 服务端不产生此类输出；若将来某插件产生，表现为多行而非原地覆盖。

## 影响

- `Terminal.tsx` 的输入路径（`onData` 手搓回显/退格/历史）**整体废弃**
- `terminal-session-manager.ts` 持有 xterm 实例的部分需要改为持有行缓冲；
  ADR-067 的"连接与缓冲常驻管理器、组件卸载只 detach 渲染层"这一保活语义**必须保持不变**
- WS 消息契约不变（仍是 `stdout`/`stderr`/`state`/`stdin`），`resize` 对新输出区无意义但保留不发
- 终端相关既有测试需按新结构更新断言（不得弱化）

## 验证

- 命令栏：`←→` / `Home` / `End` / `Ctrl+A` / `Ctrl+W` 全部标准语义
- 中文输入法输入含空格的中文命令，无乱码、无重复回显
- 灌 10000 行日志滚动 ≥50fps（Chrome Performance 面板实测）
- ANSI 着色与 xterm 渲染结果肉眼一致；未知转义不产生可见垃圾字符
- 停机态输入禁用并给出原因与直达动作
- ✱ 真机（FR-277 主机，HTTP 非安全上下文）复验粘贴与复制
