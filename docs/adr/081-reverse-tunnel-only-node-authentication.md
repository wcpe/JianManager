# ADR-081: Worker 仅通过已认证的反向隧道接收控制面指令

- **日期**: 2026-07-27
- **状态**: accepted
- **取代关系**: 取代 ADR-066 的「双模式：隧道优先、CP 直拨回退」及其 Worker gRPC 入站端口保留决定；gRPC 仍是 Control Plane 与 Worker Node 间唯一 RPC 协议，ADR-002 的协议选择不变。
- **关联**: ADR-039（节点 UUID 身份）、ADR-061（WS 令牌密钥）、ADR-066（反向隧道）。

## 上下文

ADR-066 为存量 Worker 的升级窗口保留了 CP→Worker 直拨 gRPC 回退。这使 Worker 继续监听入站 gRPC 端口，且 CP 在注册和心跳期间会按 Worker 上报的 Host/GRPCPort 主动连接。该暴露面与「Worker 不开放任何 CP 直拨能力」的安全边界冲突。

审查还发现心跳流允许缺少 node-secret 的旧版兼容路径，注册可按请求声明的 Host 识别旧节点。这两个兼容路径会使未认证调用影响节点状态，不能继续保留。

## 决策

1. Worker 不再监听或注册供 CP 直拨的 gRPC 服务。所有 CP→Worker RPC（包括终端会话）只能经 Worker 主动建立的 gRPC 反向隧道承载。
2. ClientPool 只从活跃反向隧道取得节点通道；无活跃隧道时节点不可调用，返回既有离线语义。不得拨号到节点上报的 Host、GRPCPort，也不得保留备用连接池。
3. Worker 的 Register 重注册必须同时出示 node-uuid 与 node-secret；缺失、单独携带或不匹配一律拒绝。删除以 name + Host 为依据的旧版重注册路径。
4. Heartbeat 在处理第一条负载前必须验证 metadata 中 node-secret 与请求 node_uuid 的对应关系；无凭据、未知节点或凭据不匹配一律拒绝，且不得更新节点状态、指标或下发任何数据。
5. Worker 只在成功注册并拿到非空的专用 WS 令牌密钥后启动依赖该密钥的 WS 服务；关闭时同步关闭 WS 服务与反向隧道，避免残留监听或泄漏连接。

## 理由

- 单一承载方向消除了 Worker 的外部 RPC 入站面，满足 NAT、内网和最小暴露面要求。
- UUID 与 secret 共同绑定身份，不把可伪造的 Host、名称或心跳负载当作认证因子。
- fail-closed 能保证认证失败路径没有数据库状态、指标、任务或密钥下发副作用。

## 后果

- 未支持反向隧道、未持久化节点身份或未使用专用 WS 密钥的旧 Worker 必须升级后才能重新上线；不再提供 CP 直拨兼容窗口。
- 节点离线或隧道重连期间，CP→Worker 操作返回现有节点不可用错误，调用方不得自行回退到网络直拨。
- `grpc_port` 仅保留历史数据兼容，不再作为 Worker 监听或 CP 拨号配置；后续数据迁移可另行清理该字段。

## 替代方案

- **继续保留直拨回退并增加 mTLS**：仍要求 Worker 开放入站端口，且维护两条承载路径；不满足本次「仅反向隧道」决定。
- **按 Host 匹配旧节点**：Host 是请求可声明的数据且 NAT/代理环境不稳定，不能作为身份凭据。
- **允许无 secret 心跳但不下发密钥**：即使不泄漏密钥，匿名调用仍可改写节点在线状态、指标和实例对账，不能接受。
