# ADR-065: 开发版本命名——`-dev` 预发布标识指向下一目标版

- **日期**: 2026-07-12
- **状态**: accepted

## 上下文

`internal/version/version.go` 的 `var Version` 是版本号单一真值（构建期经 `-ldflags` 注入，见 ADR-036）。此前的隐性约定是「`version.go` 对齐**最新已发布版本**」（注释原文：「对齐最新已发版本，消除与 CHANGELOG 漂移」）。该约定只在「刚发完版、还没开始下一版开发」的瞬间成立；一旦在 `dev` 上继续积累提交，`version.go` 仍停留在上个 tag 的裸版本号（如 `v0.14.0` 已发布后源码仍写 `0.14.0`），于是**开发态构建出来的二进制会谎报成一个已发布的版本号**——本仓真实踩到：`dev` 领先 `v0.14.0` 达 15 个提交（含 FR-278/279/280 等 `feat`），但本地 `make dist` 产物与部署到真机的 CP 仍报 `0.14.0`，导致「面板显示 0.14.0、实则含大量未发布变更」的漂移，也让「这台机上到底是不是最新」无法从版本号判断。

项目已有 `sdd-publish-snapshot`（发开发版快照）技能，其流程明确依赖「按**版本来源约定**命名」，但仓库从未定义过这个约定——即开发态该报什么版本号是空白的。

候选方案：
1. **保持「= 最新已发版本」**：漂移无解（现状即证）。
2. **Maven 式 `X.Y.Z-SNAPSHOT`**：语义对，但 `-SNAPSHOT` 是 Java 生态惯例，与 Go/SemVer 心智不符。
3. **裸 `X.Y.Z`（下一目标版，不带后缀）**：无法与「真的发布了 X.Y.Z」区分，且 SemVer 上 `X.Y.Z-dev < X.Y.Z`，裸号会让开发版**大于等于**目标正式版，排序错误。
4. **`X.Y.Z-dev` 预发布标识（选中）**。

## 决策

确立版本号生命周期：`version.go` 恒等于「**当前应报告的版本**」，取三种形态之一——

- **正式发布版** 裸 `X.Y.Z`：仅存在于打了 tag `vX.Y.Z` 的那个提交。
- **开发版** `X.Y.Z-dev`：两个 tag 之间的所有开发态；`X.Y.Z` = 按 SemVer 推断的**下一个目标版本**。
- **候选版** `X.Y.Z-rc.N`（可选）：冻结候选时短暂使用。

`-dev` 是 SemVer 预发布标识，天然满足不变式 `上个正式版 < 开发版 < 目标正式版`（如 `0.14.0 < 0.15.0-dev < 0.15.0`），既消除漂移又保持可比。发版时 `sdd-release-version` 去 `-dev` → 打 tag → 立即 bump 到下一个 `-dev`，重开发开发窗口。完整规则与联动（PRD/CHANGELOG/快照/内嵌资产/自更新）见 `.claude/rules/versioning.md`。

本 ADR **取代**先前「`version.go` 对齐最新已发版本」的隐性约定。

## 影响

- **代码**：`version.go` 默认值即刻从 `0.14.0`（已发布）改为 `0.15.0-dev`（下一目标，dev 已含 `feat`→MINOR）。构建产物、自更新 feed、内嵌 Worker 清单（FR-278）随注入值一并变为 `0.15.0-dev`，四处同源一致。
- **安全性核验**：自更新版本一致性判定 `versionDiffers()` 仅做**字符串判等**（`TrimPrefix "v"` 后 `!=`），非序比较；Worker 资产解析用「精确相等」匹配，`version.Version` 与内嵌清单同源同值；`version.Version` 经 `url.PathEscape` 进 `/worker-assets/<version>/…` 路径，`-` 属 SemVer 合法且 URL 安全。故 `-dev` 后缀端到端安全，无需改动比较/解析逻辑。
- **约束**：不得对 `version.Version` 引入严格 `^\d+\.\d+\.\d+$` 校验（会误拒预发布号）。
- **流程**：`sdd-release-version` 与 `sdd-publish-snapshot` 以本 ADR 与 `versioning.md` 为「版本来源约定」的落地依据。
