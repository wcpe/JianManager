# ADR-092: 实例配置源明面化与 MC 直探能力

- **日期**: 2026-09-21
- **状态**: accepted
- **关联**: FR-446 / FR-447 / FR-451 · 增强 FR-031（配置版本化）/ FR-233（实例配置编辑）/ FR-060（实例指标采集）

## 上下文

**配置面分散且深藏**：实例的启动命令 / JVM 参数走 `startCommand` / `launchSpec`（FR-233 可编辑但入口在实例配置一节），`server.properties` 只能经文件管理器（FR-008）或结构化字段补丁（FR-031 的 `config_write_fields`，入口更深）修改。运维反馈：**"不要放到犄角旮旯里，放出来配置，或者直接引用文件"**。

**采集强依赖探针**：MOTD / 版本 / 在线人数 / 玩家名单目前**全部走 ServerProbe**（第三方 Bukkit 插件，Prometheus `/metrics` + 反向 WS 桥）。全仓**没有** Minecraft Server List Ping（SLP）或 GameSpy4 Query 协议客户端——探针未装 / 未连 / 挂在非 Bukkit 服务（代理、二进制）时，这些基础信息**一个都拿不到**，界面只能显示 `-1` / `--` 占位符（真机确认：64 张卡片玩家数全是 `-1`）。

用户明确要求：① 启动参数与 `server.properties` 关键项**明面化**（可编辑或引用文件）；② 直探要 **SLP + Query**。

## 决策

1. **配置项二态来源（内联 vs 文件引用）**：每个受管配置项显式声明来源——
   - **内联值**：平台持有该值，可编辑、可版本化、可跨实例下发（沿用 FR-031）。
   - **文件引用**：该项由外部文件提供，平台**不覆写**，只解析并展示生效值预览（只读）。
   两态互斥、显式声明，避免"平台改了但被文件覆盖"的静默冲突。

2. **明面化入口**：启动命令 / JVM 参数 / `server.properties` 关键项（含 `enable-query` / `query.port` / `view-distance` 等）在实例详情/配置区**直接可见可改**，不再要求进文件管理器。

3. **MC 直探作为独立采集源**：
   - **SLP（Server List Ping）**：零配置，任何 MC 服内建支持；取 MOTD / 版本 / 在线人数 / 最大人数 / favicon。
   - **Query（GameSpy4）**：需 `enable-query=true` + `query.port`；取**准确实名玩家名单** / 插件列表 / 地图名。

4. **采集优先级链**：`探针 → SLP → Query → 不可用`。同一指标多源时**以探针为准**（探针最细：TPS/MSPT/JVM/世界）；探针缺该指标时回落直探；都无则显示"不可用"（**不留 `-1`/`--` 垃圾占位**）。

5. **`enable-query` / `query.port` 由平台经决策 1 注入**：开 Query 需要改 `server.properties` 并重启；平台把这两项纳入受管配置项，降低运维心智，并复用既有端口分配（`allocPortsForNode`）。

## 理由

- **为什么配置源要二态**：运维有的项要平台统一管（如 `query.port` 需与端口分配一致），有的项要自己维护文件（如复杂 MOTD 多行）。一刀切"全内联"或"全文件"都会挡住一半场景。
- **为什么直探独立于探针**：探针是**第三方 Bukkit 插件**——覆盖不到代理（BungeeCord 无法加载）、二进制服务、未装探针的服、探针挂掉的服。SLP 是 **MC 协议内建**，只要服在跑就能答，是"保底可见"的关键。
- **为什么 SLP 优先于 Query 做保底**：SLP 零配置、普适（代理也支持）；Query 需改配置且需分配端口。保底用 SLP，增强用 Query。
- **为什么要 Query**：SLP 的 player sample 不保证返回、也不含 UUID；**实名名单只有 Query 能给**（用户明确要"探索玩家"）。
- **为什么探针优先**：探针提供 TPS/MSPT/JVM/分世界等直探拿不到的深度指标；直探是补充与保底，不是替代。

## 后果

- 新增配置源模型（`ConfigSource`：`inline` | `file`），落到既有 `config_write_fields` 与实例配置 API。
- 新增 MC 直探客户端（SLP + Query），落在 Worker 侧（与探针抓取同层，避免 CP 直连游戏端口）。
- 采集编排（FR-447）新增降级链与"不可用"语义；前端 `-1`/`--` 占位符清除。
- `enable-query` / `query.port` 纳入受管配置项；跨实例端口唯一性校验（`schema/crosscheck.go`）扩展到 query.port。
- 与 ADR-091 协同：能力画像的"数据来源偏好"读本次的优先级链。

## 备选

- **只做 SLP（不做 Query）**：被否——用户明确要实名玩家名单，SLP 给不了。
- **只做 Query（不做 SLP）**：被否——Query 需改配置 + 分配端口，SLP 零配置更普适，且代理/未配置服只有 SLP 可用。
- **配置只保留内联**：被否——用户明确要"直接引用文件"。
- **配置只保留文件引用**：被否——`query.port` 等需与平台端口分配一致，必须平台持有。
- **直探放 CP 侧**：被否——CP 不直连游戏端口（ADR-003/081 的进程边界），且多节点下 CP 未必能连通游戏服内网。
