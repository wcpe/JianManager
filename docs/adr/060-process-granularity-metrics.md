# ADR-060: 进程粒度监控采集采用受管实例 TOPN 快照

- **日期**: 2026-07-06
- **状态**: proposed（待用户审核；关联 FR-170）
- **关联**: FR-170、FR-169、ADR-013、ADR-014、ADR-016

## 上下文

FR-169 的监控页升级把“进程 TOP10 tooltip”拆为 FR-170。当前 ADR-013 已定义节点/实例/世界时序指标的降采样存储，ADR-014/016 定义 ServerProbe 作为实例富指标源，但它们不覆盖 Worker 主机上的进程粒度视图。

如果直接采集全机完整进程表，容易引入三个问题：数据量过大、命令行泄露敏感参数、以及 UI 把非受管进程误读为平台实例问题。

## 决策

FR-170 只采集“JianManager 受管实例及其子进程/容器”的 TOPN 快照，不做全机进程审计。

1. **采集边界**：Worker 以实例 PID 文件、daemon wrapper 进程树、direct 进程树和 docker 容器 ID 为边界，识别每个受管实例的进程集合。默认不采集无归属的系统进程。
2. **指标范围**：每个进程样本包含 `pid`、归属实例、进程名、CPU 百分比、RSS 内存、读写 IO 字节增量、启动用户（可得时）和截断后的命令摘要。完整命令行、环境变量和参数原文不入库。
3. **TOPN 语义**：Worker 每次心跳只上报每实例 CPU 或内存占用最高的前 N 个进程（默认 10），CP 保存短期 raw 快照并为监控页提供查询。FR-170 不做一年级进程明细保留。
4. **存储模型**：CP 新增进程指标快照表或在现有时序体系旁新增窄表，按实例、时间、排序键查询；TTL 短于常规指标，避免写放大。
5. **UI 消费**：监控总览和实例详情只展示 TOP10 tooltip/面板，用于排障定位，不提供 kill、优先级调整或任意进程管理操作。
6. **兼容性**：Worker 无法获取某平台的进程字段时，字段为空或省略；CP 和前端以缺测展示，不伪造 0。

## 理由

- 用户目标是定位受管实例资源热点，不是提供通用主机进程审计。
- 限定为受管实例能减少隐私和安全风险，并保持数据量可控。
- TOPN 快照足以支持 hover 排障场景，避免把进程级数据纳入 ADR-013 的长期降采样体系。
- Worker 仍不访问数据库，数据经心跳/gRPC 回到 CP，符合架构不变量。

## 后果

- `proto/worker.proto` 需要为心跳追加进程 TOPN 样本，向后兼容。
- Worker metrics collector 需要按平台实现进程树/容器归属识别和 IO/CPU 采样。
- CP 需要新增短期存储、查询接口和 TTL 清理。
- 前端监控页需要明确“仅受管实例进程”的文案，避免误解为全机进程列表。

## 替代方案

- **采集全机进程表**：排障能力更大，但隐私、数据量和权限边界风险高，放弃。
- **只靠 ServerProbe JVM 内部线程指标**：对 JVM 内部有帮助，但不能定位 wrapper、Java 子进程、容器和 IO 热点，不足以满足 FR-170。
- **把进程数据纳入一年时序留存**：长期分析能力强，但写入量与隐私成本高，超出 FR-170，放弃。
