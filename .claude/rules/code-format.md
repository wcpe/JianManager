# Go 源码格式

> 所有 Go 源码必须通过 `gofmt`。这是 Go 生态的强制惯例，不是风格偏好。

## 规则

**提交前必须 `gofmt` 通过**（零不合规文件）。

```sh
sh .claude/scripts/check-gofmt.sh          # 检查（期望 0 命中）
sh .claude/scripts/check-gofmt.sh --fix    # 就地格式化
```

## 为什么

1. **没有门禁时它会静默退化**。本文立规前（2026-11-10 实测）全仓有 **34 个** gofmt 不合规文件，
   而 CI 与 `golangci-lint` **都没启用任何格式 linter**（`.golangci.yml` 只开了 errcheck/govet/
   staticcheck 等 8 个，不含 gofmt/gofumpt）—— 也就是说这批不一致可以无限期存在，没人会发现。
2. **格式噪音会淹没真实 diff**。不合规文件一旦被下一个改动者用 IDE 自动格式化，
   就会产生一堆与本次改动无关的空白 diff，评审时真正要看的一行反而淹没在里面。

## 已知行为：gofmt 会重排注释

Go 1.19 起 gofmt 对文档注释有一套重排规则，会做两类**看起来像“改内容”**但实为排版的改动：

```go
// 改前（缩进用空格）              // 改后（gofmt 标准）
// 说明：                        // 说明：
//     - 第一条                   //   - 第一条
//     - 第二条                   //
// 下一段                        //   - 第二条
                                 //
                                 // 下一段
```

具体：
- 缩进的续行会改用 **Tab**（`//\t`），并视为文档代码块
- 列表/段落之间会**插入空 `//` 行**分隔

**中文注释同样适用**：`//     停滞看门狗判卡死` 会变成 `//\t停滞看门狗判卡死`。
文字内容一字未变，只是排版对齐标准。评审时看 `git diff -w` 可确认无实义改动。

## 版本一致性

本项目 `go.mod` 声明 **Go 1.26.2**，CI 固定用该版本。
但 gofmt 的输出**跨大版本基本稳定**，实测 2026-11-10：同一批文件在 1.26.2 与 1.27.3
下 `gofmt -l` 结果均为 0 命中。改 Go 大版本时请重跑一次门禁确认。

## 门禁

| 位置 | 命令 |
|---|---|
| 本地/评审 | `sh .claude/scripts/check-gofmt.sh` |
| CI | 在 go-quality job 里同上，失败即阻断 |

扫描范围：`internal apps scripts proto .`（排除 `vendor/`）。
