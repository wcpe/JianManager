# 主线外记录可直接删除

> **判据只有一个：是否已合入 `master`。** 合入前后是两套规则。

## 为什么需要这条

主线之外的 FR/ADR 还没被任何人依赖。方向改了、需求撤了，**删掉整行 / 整个文件**就不会留下痕迹。
若按「只追加 + 标记废弃」处理，PRD 表和 ADR 目录会沉淀一批 `❌ 已废弃` / `superseded-by`
——它们对读者没有信息量（没人见过那条需求），却让登记表越来越难读。

**反面实例**：曾有两条记录在 2026-10-06 同批创建，10-09 就被后续决策推翻
（业务组件不该并入组件库）。两条当时按「保留 + 标废弃」处理，于是 PRD 里多了一行
从未交付过的 `❌ 已废弃`，ADR 目录多了一个 `superseded-by` 的死号。这正是本规则要避免的。
按本规则，这两条后来被直接删除；空出的 FR 号已回填给一个新范围的登记（尚未合入 master，故可回填）。
本规则的适用边界见下方「规则」两节。

## 规则

### 未合入 master（分支上）

| 对象 | 处置 |
|---|---|
| FR | **删除整个 FR 行**（不留 `❌ 已废弃`） |
| ADR | **删除整个文件**，同时从 `docs/adr/README.md` 移除条目 |
| spec 目录 / impl 记录 | 直接删除 |
| CHANGELOG 条目 | 有则删除 |

**要求**：删完要检查反向引用——其他 ADR/PRD/spec 里若引用了被删的编号，一并改写措辞
（不是改成「已废弃」，而是把那段论证改成不依赖该编号的表述）。

**编号**：删除后该号**空出**。后续新增 FR 按 `prd-authoring.md §5` 的「取当前最大号 +1」继续，
**不回填空号**；除非该空号产生于「同批规划中途撤销」，且补号能消除一处实际的编号断档
（由人判断，不默认补）。

### 已合入 master

恢复 [doc-evolution.md](doc-evolution.md) 的现行规则，不再适用本规则：

| 对象 | 处置 |
|---|---|
| FR | 标 `❌ 已废弃`，**留在 §4 表内**（外部可能已引用该号） |
| ADR | 新 ADR 引 `superseded-by`，**旧 ADR 不删**（历史决策本身是资产） |

理由：一旦进了主线，这个号就进了「历史」——别人可能引用了它、往后的复盘要读它。
此时删掉会让引用悬空，代价远大于登记表的冗余。

## 判定「是否已合入」的具体做法

```bash
# 该 FR/ADR 对应的 commit 是否已在 master 上
git merge-base --is-ancestor <commit> origin/master && echo "已合入：走保留规则" || echo "未合入：可删"
```

注意别被 squash 合并骗：合并方式可能是 squash，此时原 commit 不在 master 上，
**但内容在**。用 tree 比对确认：

```bash
git diff --stat <分支> origin/master -- <相关文件>   # 无输出 = 内容已等价
```

## 自检

- [ ] 要删的记录，其编号在 `origin/master` 上不存在
- [ ] 删除后全仓 `grep` 该编号，无非预期的悬空引用
- [ ] 若删的是 ADR，`docs/adr/README.md` 条目已同步移除
- [ ] 没有因为「想留个教训」而保留主线外的废弃记录——教训写进规则或 ADR 正文，不靠遗留条目承载
